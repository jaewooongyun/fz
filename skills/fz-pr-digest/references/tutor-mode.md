# Tutor 모드 사양 (fz-pr-digest)

> SKILL.md의 Tutor 티어가 참조한다. Light/Standard/Deep 티어에는 적용하지 않는다.
>
> ⛔ **규칙 정본은 `modules/explanation-protocol.md` 다.** 폐포 5축 · 어휘 등급 · 게이트
> G1~G8 · 층위 · 출력 구조는 그 모듈에 있고 **여기서 재정의하지 않는다.**
> 이 문서는 PR 맥락 고유분만 담는다.

## 1. 축 전환 — 이 티어가 다른 티어와 다른 점

Light/Standard/Deep은 **diff를 출력의 축**으로 삼는다. Before/After가 뼈대이고, 변경되지 않은
코드는 아키텍처 맥락 섹션에 배경으로만 언급된다.

Tutor는 축을 바꾼다. **기능이 축이고 diff는 그 안의 표시**다.

```
Standard의 질문:  "무엇이 어떻게 바뀌었나?"       → 축 = diff
Tutor의 질문:     "이 기능은 어떤 코드들이
                   어떻게 맞물려서 동작하나?
                   그중 이번에 손댄 곳은 어디인가?"  → 축 = 기능
```

축을 바꾸는 이유는 독자가 막히는 지점이 다르기 때문이다. 처음 보는 사람은 바뀐 줄을 못 읽어서
막히지 않는다. 바뀐 줄이 **의존하고 있는, 바뀌지 않은 구조**(프로토콜, 주입 지점, 등록 코드,
호출자)를 몰라서 막힌다. diff를 축으로 두는 한 그 구조는 출력에 등장할 수 없다.

⛔ 따라서 Tutor에서는 Standard의 범위 규칙("diff에 포함된 변경만 해설한다")을 **적용하지
않는다**. 대신 정본 모듈의 폐포가 범위를 정한다. 규칙이 없는 것이 아니라 다른 규칙을 쓴다.

---

## 2. Seed — 이 티어가 정하는 것

정본 모듈은 seed 산출을 호출 스킬에 맡긴다. Tutor의 seed는 이렇게 정한다.

```
seed = diff의 변경 심볼 (추가·수정·삭제된 함수·타입·프로퍼티)
```

⛔ diff가 아니라 **심볼**이 seed다. 한 줄 수정도 그 심볼 전체를 seed로 올린다.
그래야 정본 §3.2의 관계 탐색이 성립한다.

---

## 3. 슬롯 값 — 이 티어가 채우는 것

정본이 비워 둔 두 자리를 Tutor는 이렇게 채운다.

| 자리 | Tutor의 값 |
|------|-----------|
| 매핑 블록 `상태` 슬롯 | `변경됨` 또는 `변경 없음 — 기존 구조` |
| 출력 §7-A 좌표 표시 | 흐름 말미에 `이번 PR이 손댄 지점: {번호}` |

`상태` 라벨이 있어야 독자가 "새로 생긴 것"과 "원래 있던 것"을 구분한다. 이 구분이 없으면
전부 새 코드로 오독한다.

좌표 표시가 축 전환을 실현하는 장치다 — diff가 흐름 안의 좌표로 표시된다.

---

## 4. 실행

```
1. diff에서 변경 심볼 추출 → seed (§2)
2. `{플러그인 루트}/modules/explanation-protocol.md` + `{플러그인 루트}/modules/explanation-output.md` Read → §9 절차 T2~T6 수행
3. 출력 시 §3의 슬롯 값 채움
4. 저장: ${WORK_DIR}/pr-digest-tutor.md
```

⛔ 게이트·폐포·어휘 등급의 세부는 정본 모듈을 따른다. 여기에 복제하지 않는다 —
두 문서에 같은 규칙이 있으면 서서히 어긋난다.

---

## 5. 체크리스트 (PR 고유분만)

- [ ] seed가 diff의 변경 **심볼**인가 (파일 아님)
- [ ] 매핑 블록마다 `상태` 라벨이 있는가
- [ ] 흐름 말미에 이번 PR이 손댄 지점이 표시됐는가
- [ ] 정본 모듈의 체크리스트(§10)를 통과했는가

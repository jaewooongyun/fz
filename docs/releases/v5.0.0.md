# v5.0.0 (2026-11-13) — 누수 검사는 파일 내용만 봤다 — 커밋 신원 · 메시지 · 태그 · 릴리스 본문 · push 까지 한 규칙으로 본다 [MAJOR]

출하 게이트의 누수 검사는 작업 트리의 파일 내용만 봤다. 커밋 작성자 · 커밋 메시지 · 태그 주석 · 릴리스 본문 · push 는 어느 검사도 보지 않았고, 커밋 훅은 CHANGELOG · 릴리즈 노트 · 작업 로그를 예외로 건너뛰었다. 규칙이 훅과 게이트에 사본으로 흩어져 있어 한 벌만 고쳐지기도 했다. 이 판은 규칙을 정본 모듈 하나로 모으고, 커밋 훅 · push 훅 · 출하 게이트 · 릴리스 본문 검사가 그 모듈을 함께 부른다.

같이 바꾼 것이 셋 있다. 예시 · few-shot · fixture 의 이름과 좌표를 합성 도메인 하나로 통일했다. 실행 기록은 저장소 밖에 쓴다. 옛 판 릴리즈 노트를 걷고 CHANGELOG 는 판마다 한 줄만 남긴다. 공개 저장소는 이 판의 트리로 이력을 새로 시작한다 — 그래서 MAJOR 다.

Closes: F-594, F-600, F-604

## 쓰는 쪽에서 달라지는 점

- **커밋 훅**이 CHANGELOG · 릴리즈 노트 · 작업 로그 · 승격 원장도 검사한다. 비공개 규칙 파일은 `--rules` > env `FZ_NEUTRALIZE_RULES` > git 설정 `fz.neutralizeRules` 순으로 찾는다. 없으면 내장 규칙만 보고 안내 한 줄을 낸다(유지관리자 표지 `fz.maintainer` 가 참이면 막는다 — 규칙 파일이 비어 규칙이 0개일 때도 막는다)
- **push 훅**이 생겼다. `core.hooksPath` 가 `.githooks` 면 push 때 돈다. 우회(`git push --no-verify`)한 push 는 다시 검사하지 않는다 — 출하 게이트는 출하 범위(직전 출하 태그 뒤 HEAD 까지의 커밋)와 로컬 태그만 본다
- **출하 게이트** `check_release_sync.sh --release` 는 `--rules <파일>` 을 명시로 요구한다. 없으면 exit 2 다. 비공개 규칙이 없으면 빈 파일을 준다
- **출하 게이트의 finding 표**가 필수다. CHANGELOG 최상단 절에 표도 '닫은 finding 없음' 표지도 없으면 `--release` 가 실패한다. `--release` 없는 기본 검사는 그대로다
- **릴리스 발행**은 본문을 노트 파일로만 올리고(`--notes-file`), 발행 뒤 `leak_rules.py --release-body <태그>` 로 다시 본다
- **실행 기록**은 `${FZ_RUN_STATE:-~/.fz/runs}/experiment-log.md` 에 쓴다. 추적 파일에 실행 행이 들어오면 `check_ab_protocol.py` 가 exit 1 이다
- **회귀 러너**(`tests/workflows/effort-arg.js` · `default-off-regression.js`)의 기준은 환경 변수 트리 > 환경 변수 SHA > 저장소 고정본 순이다. 명시한 선택자를 읽지 못하면 고정본으로 내려가지 않고 exit 2 다
- **clone** 은 `scripts/isolated_clone.sh <원본> <대상>` 으로 만든다(태그 없이 · 신원과 훅 경로를 옮긴다 · 옮긴 신원의 이름이나 메일이 신원 정책에 걸리면 판정 불가로 끝난다)
- **예시 이름**이 바뀌었다. 리뷰 렌즈 few-shot · 리뷰 모듈의 사례 · 가이드 예시 · 품질 fixture 의 기능 이름 · self-test 표본이 주문 앱 이름을 쓴다. 옛 이름을 인용한 메모나 프롬프트는 맞지 않는다
- **옛 판 릴리즈 노트 파일은 없다.** 판별 변경은 CHANGELOG 의 제목 한 줄로만 남는다

## 기준선이 옮겨진 곳

이 판을 사이에 둔 측정은 아래 넷 때문에 그대로 비교할 수 없다.

| 무엇 | 왜 달라지나 |
|---|---|
| 품질 fixture 의 지침 · 토큰 이름 · 기능 이름(파일 경로 포함) | fixture 저장소의 커밋 해시가 A/B 입력 해시다 |
| 리뷰 렌즈 정의의 few-shot · 예시 문구 | 렌즈 워커의 문맥이 달라진다 |
| 계측기(`scripts/fz_wf_metrics.py`)의 워커 기록 읽기 · 심볼 도구 점검 · 종료 훅 훑기, 심볼 도구를 가진 워커 정의 13개(`agents/`), 워크플로 머리말 한 문장 | 계측기와 워커의 지문이 달라진다. 이 판 앞뒤에서 잰 수치는 새 기준선을 다시 재기 전에는 비교할 수 없다 |
| `tests/fixtures/baseline-manifest.json` 재동결 | 감량 기준점이 이 판의 트리로 옮겨진다 |

재동결한 매니페스트의 `git_head` 는 정리 전 커밋을 가리키고 미커밋 파일 수가 함께 적혀 있다 — 이 판의 트리는 커밋 전에 동결했다. 새 이력에는 그 커밋이 없다.

## 하지 않은 것

- ⛔ **이력 처리는 이 판의 트리가 하지 않는다.** 새 루트 커밋 · 옛 태그와 릴리스 정리는 출하 절차의 몫이다. F-592 는 게이트 쪽(위 표의 출하 게이트 · push · 릴리스 본문 행)만 닫혔고 이력 쪽이 남아 `Closes:` 에 적지 않았다
- **품질 fixture 지침의 규칙 수와 순서는 그대로다.** 라벨이 규칙을 줄 번호로 가리킨다. 바꾸면 라벨과 기대 색인을 함께 다시 써야 한다
- **도구 동작의 실측 비율**(재현율 · 오탐 비율 · N 중 M)은 지우지 않았다. 검사와 절차의 근거다
- **실행 비트 없는 셔뱅 파일**은 고치지 않았다. 출하 게이트가 허용 목록으로 다룬다
- **검사 범위 밖의 이력은 보지 않는다.** 로컬 태그가 범위 밖의 커밋을 가리키면 출하 게이트는 그 커밋을 검사하지 않고 판정 불가로 끝난다 — 그 태그를 지우거나 태그 없는 격리 clone 에서 출하한다

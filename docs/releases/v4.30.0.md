# v4.30.0 (2026-09-06) — codex 라는 이름이 두 가지를 가리키고 있었다 [MINOR]

`codex` 는 **벤더 CLI 실행 파일**이면서 동시에 **fz 스킬 이름**이었다. 전자는 바꿀 권한이 없고
후자는 우리 것인데, 같은 토큰이라 40개 파일에서 뒤섞여 있었다. 전역 치환을 돌리면 `codex exec`
348 곳이 깨진다.

해법은 규칙을 잘게 쪼개는 것이 아니라 **경계 문자를 이용해 분리**하는 것이었다. 치환 대상은
전부 하이픈·언더스코어로 연결된 복합어(`fz-codex` · `codex-skills` · `codex-exec` ·
`codex_*_schema` · `get_codex_skill_path` …)이고, 보존 대상은 전부 공백이나 슬래시로 분리돼
있다(`codex exec` · `~/.codex/` · `Bash(codex *)`). 구조적으로 겹치지 않는다.

## 무엇을 바꿨나

| 종류 | 변경 |
|---|---|
| 디렉토리 | `codex-skills/` → `gpt-skills/` · `skills/fz-codex/` → `skills/fz-gpt/` |
| modules | `codex-strategy` · `fz-codex-bash-hygiene` · `fz-codex-subcommands-{core,aux}` |
| scripts | `codex-exec` · `check-codex-flags` · `setup-codex-skills` · `validate-codex-output` |
| schemas | `codex_{base_issue,gate_verdict,peer_review,review,verification}_schema.json` |

67 파일 · 357 회. 커밋은 기능 단위 여섯 개로 나눴다.

## 검증 — 개수를 세는 것이 증거다

보존 대상 일곱 종의 개수를 치환 전후로 대조했다. 하나라도 **줄면** CLI 계약이 훼손된 것이다.

| 보존 문자열 | 개수 |
|---|---:|
| `codex exec` | 108 |
| `Codex CLI` | 53 |
| `~/.codex/` | 26 |
| `.codex/skills` | 20 |
| `codex mcp` | 7 |
| `Bash(codex *)` | 3 |
| `codex --version` | 2 |

치환 로그(357회)만으로는 **무엇이 안 깨졌는지** 알 수 없다. 108 이 108 로 남았다는 사실이
"CLI 호출이 살아 있다"의 직접 증거다.

잔량 카운터도 세웠다. 개명 전 실측 **67**(= 계획이 예측한 값), 개명 후 **0**.
⛔ 이 오라클에 `--include="*.md"` 를 붙이면 안 된다 — 코드 아홉 건이 남아도 초록불이 켜진다.

## ⭐ 검사기의 대상 목록이 따로 있었다

가장 값이 큰 발견이다. 개명 후 고치지 않으면 **새 디렉토리가 검사에서 조용히 빠지는** 자리가
여덟 곳 있었다.

- `.githooks/pre-commit` 의 `SCOPED_RE` — 확장자가 없는 파일이라 첫 탐색 grep 에 원리적으로
  안 잡혔다(리포 전체에 확장자 없는 파일은 둘뿐이다)
- `CLAUDE.md` In-scope 목록 · Directory Structure · scripts 설명
- `lint_contracts.py` 정규식·`WIRING_DIRS` · `lint_doc_freshness.py` 제외 목록
- `resolve-plugin-root.sh` 루트 마커 · `check-gpt-flags.sh` 기본 TARGET

코드 참조는 깨지면 소리가 난다. 검사기 목록은 **검사가 정상적으로 돌면서 대상만 비어 있다** —
`health-check exit 0` 으로 잡히지 않는다.

⛔ 분류 정정도 있었다. 여덟 중 `resolve-plugin-root.sh` 는 fail-**closed** 이고(틀리면 비0 종료),
`lint_doc_freshness.py` 의 `codex-skills` 제외값은 그 디렉토리가 애초에 SCAN_DIRS 에 없어
**무효 항목**이었다. 그리고 `CLAUDE.md` Directory Structure 는 lint `#N2` 가 보호한다고 적었으나
실제 `INV` 에는 modules·guides·scripts·agents·workflows 다섯뿐이라 **보호가 없다** — 근거가
정반대였다.

## 함께 정리한 것

**고아 서브커맨드 둘을 없앴다.** `commit` 과 `config` 는 정의만 있고 호출 배선이 0건이었다.
소비자 스킬 29파일을 전수 대조했고, 같은 패턴에서 `drift` 가 4곳 잡히는 것으로 검색이 살아
있음을 확인했다. 단일 커밋 검증 기능 자체는 `gpt-exec.sh review --commit SHA` 로 남아 있다 —
사라진 것은 진입점뿐이다.

**`argument-hint` 를 6 → 10 개로 넓혔다.** `verify-gates` · `drift` · `plan` · `micro-eval` 은
배선이 있는데 선언에 없었다. 특히 `verify-gates` 는 effort 표에도 빠져 스크립트 기본값으로
흐르고 있었다 — 동작은 했지만 의도인지 누락인지 문서로 판별할 수 없었다.

**무효 effort 를 로컬에서 거부한다.** Codex CLI 는 그것을 거부하지 않는다. 실측 —
`codex exec -c model_reasoning_effort=bogus` 가 배너에 그 값을 찍고 서버까지 왕복한 뒤에야
실패한다. 오타가 조용히 통과하면 "올렸다고 믿는데 무효"가 된다.

**소스에서 사라진 스킬 심볼릭을 정리한다.** 링크 생성 루프는 소스 디렉토리를 순회하므로
이름이 바뀐 스킬의 옛 심볼릭은 영원히 남는다. dangling 만 지우고 살아 있는 링크·실제
디렉토리·`fz-` 아닌 링크는 건드리지 않는다(임시 `FZ_SKILL_TARGET` 으로 네 경우 회귀 검증).

## GPT-6 Astra

버전 플로어가 gpt-5.5 세대에서 멈춰 있었다. `gpt-6-astra` 는 Codex CLI **0.153.1** 에서 처음
등장하고 **0.153.4** 가 그것을 bundled default 로 올린다. effort 근거도 GPT-5 Prompting Guide
에서 Model guidance 로 옮겼다 — 전자는 `gpt-5.3-codex` 대상이라 Astra 를 다루지 않는다.

⛔ 공식은 xhigh 를 무조건 권하지 않는다:
> "Only use when your evals show a clear benefit that justifies the extra latency and cost."

⭐ **`ultra` 는 문서가 아니라 캐시가 답을 줬다.** 조사에서 `ultra` 는 CLI 릴리즈 노트에만 있고
모델 페이지에 없어 "확인 실패" 로 분류됐고, 그 라벨을 근거로 화이트리스트에서 뺐다. CLI 를
0.153.4 로 올린 뒤 `~/.codex/models_cache.json` 을 열자 `gpt-6-astra` 의
`supported_reasoning_levels` 에 **`ultra` 가 실재했다**(gpt-5.6 계열 동일, gpt-5.5 는 xhigh 까지).
유효한 값을 거부하는 가드를 만들 뻔했다.

⇒ 벤더 문서보다 **그 벤더 CLI 가 서버에서 받아 저장한 목록**이 최신이다. enum·플래그를 코드
가드에 박을 때는 후자가 정본이다. 그리고 **"확인 실패"는 "부재"가 아니다** — 전자는 탐색 범위의
진술이고 후자는 세계의 진술이다.

## 계획이 어떻게 고쳐졌나

Codex 교차검증이 `needs_revision` 과 MAJOR 일곱 건을 냈고 전부 실측으로 확인됐다(반박 0건).

| 지적 | 실측 |
|---|---|
| `health-check exit 0` 오라클이 환경 의존 | codex 부재 시 UNRUN → exit 2 |
| verify 가 변경 전체를 측정 안 함 | 최종 grep 이 한 패턴만 봄 |
| "7지점 전부 fail-open" 이 사실과 다름 | 하나는 fail-closed, 하나는 무효 |
| 파일 수 과소 | 29 → **67** |
| `argument-hint` 자기모순 | 고아 제거 시 12 가 아니라 10 |
| prune 테스트가 실제 경로 오염 | `TARGET_DIR` 하드코딩 |
| 자기 Anti-Pattern 위반 | 제약 문구가 릴리즈 절차와 충돌 |

⛔ 그리고 이 세션에서 **대상 집합을 만드는 필터가 조용히 잘라내는 실패가 네 번** 났다 —
`--include="*.md"`(코드 아홉 건 누락) · 확장자 필터(`.githooks/pre-commit` 누락) ·
경로 앵커(releases 열아홉 개 혼입, 88 로 계수) · 부분 문자열 매치(거짓 양성). 매번 다른
필터인데 결과는 같았다. **필터는 오라클·대상목록·집합산출 세 곳에 복사된다.**

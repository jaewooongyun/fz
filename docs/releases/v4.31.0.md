## lint SSOT 파서 — 조용한 fail-open

⭐ SSOT 를 2-역할로 넓히는 것은 한 줄 편집처럼 보이지만, 그대로 하면 **lint 의 모델 검사가 통째로
꺼진다.** `MODEL_POLICY = re.compile(r"모델 정책:\s*\*{0,2}([A-Za-z0-9. ]+?)\*{0,2}\s*only")` 의 문자
클래스가 `(`·`)`·`·` 를 먹지 못한다. `모델 정책: Fable 5.1 (Lead) · Opus 5 (worker) only` 에 대해
매치가 실패하고, `current_model()` 은 빈 값을 반환하며, 그 뒤의 `stale-model-ref`·`stale-model-heading`
검사는 **비교할 현행 모델이 없어 전부 건너뛴다.** 출력은 "위반 0건"이다 — 검사 0건인데 같은 초록이다.

⛔ **감사 시점의 `stale-model-ref 0건` 도 같은 성질이었다.** 그때는 파싱이 성공했지만 SSOT 가
`Opus 5 only` 라 Fable 5 로 쓰인 문서를 stale 로 **볼 수가 없었다.** 앞은 **내용**으로, 뒤는 **파싱
실패**로 — 두 번 모두 초록불이다. 문자 클래스를 열고 역할 괄호 제거용 `MODEL_ROLE` 을 신설했으며,
`current_model()` 이 목록을 반환하고 단일 표기는 하위 호환으로 계속 파싱한다. 판별 시험은
**뮤테이션**이다 — 옛 정규식을 새 SSOT 줄에 대면 `None`, 새 정규식은 `['Fable 5.1', 'Opus 5']`.
`0-before / 0-after` 는 아무것도 구분하지 못한다.

# 2부 — 계측: 하네스가 자기 무게를 재는 눈이 없었다

앞 절(가이드 갱신)의 감사 결론은 "하네스가 해롭다는 **외부 근거는 확실**하고 fz 가 그 조건(규칙 수·강조 포화·floor
성장)을 **갖고 있지만**, fz 성능이 그로 인해 **실제로 떨어졌다는 근거는 0건**"이었다. 비용·지연은 잴 수
있었는데 **품질**이 없었고, 어느 게이트가 무엇을 잡았는지는 아무 데도 남지 않았다. 이 릴리즈는 그 눈을
심는다 — 나중에 effort 하향·스테이지 제거·규칙 감량을 **데이터로** 판정할 수 있게.

⛔ 새 로거는 만들지 않았다. 트랜스크립트가 이미 메시지별 `usage`·`effort`·`attributionSkill`·`isSidechain`
을 기록하고, 워크플로 journal 이 스테이지별 `result` 를, `fz-findings` 가 사람이 잡은 결함 131건을
남긴다. 없던 것은 셋을 **결합하는 키**와 **정기 집계**, 그리고 릴리즈마다의 **정적 부하 스냅샷**이다.

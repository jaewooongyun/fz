# v4.27.0 — 설명이 "바뀐 부분" 만 다루던 것은 지시받은 대로였다 [MINOR]

- 날짜: 2026-08-31
- 신규: `modules/explanation-protocol.md` · `modules/explanation-output.md` · `skills/fz-explain/`
- 변경: `fz-pr-digest` Tutor 이관 · `fz-peer-review` `--explain` 승격 · `intent-registry` 재분배

## 이 릴리즈의 성격

설명 기능을 고치는 작업으로 시작해, **설명 규칙 자체를 공용 자산으로 세우는 것**으로 끝났다.
증상은 "`--explain` 이 바뀐 부분만 설명한다" 였고, 원인은 모델이 아니라 규칙이었다.

---

## 1. 원인은 규칙이었다

`fz-pr-digest` 해설 원칙에 이렇게 적혀 있었다.

> diff에 포함된 변경만 해설한다. 관련 없는 코드까지 확장하지 않는다.

⛔ **지시받은 대로 하고 있었다.**

고친 것은 규칙 완화가 아니라 **축 전환**이다. diff 를 출력의 축으로 두는 한 변경되지 않은
협력자 — 프로토콜, 주입 지점, 등록 코드, 호출자 — 는 **구조적으로 출력에 등장할 수 없다.**
처음 보는 사람이 막히는 지점이 정확히 거기다.

```
전  축 = diff      "무엇이 어떻게 바뀌었나"
후  축 = 기능      "이 기능은 어떻게 동작하고, 그중 이번에 손댄 곳은 어디인가"
```

## 2. 폐포 — 축을 뒤집으면 무한 확장이 된다

"연관된 모든 구조" 를 문자 그대로 실행하면 후보가 코드베이스 전체다. 다섯 축으로 끊는다.

| 축 | 찾는 것 | 홉 |
|----|--------|:--:|
| R1 진입점 | 사용자 동작이 들어오는 첫 지점 | 최대 5 |
| R2 협력자 | seed 가 호출하는 필수 대상 | 1 |
| R3 계약 | 채택한 프로토콜 + 다른 채택자 | 1 |
| R4 배선 | 구현체 생성·주입 지점 | 2 |
| R5 소비자 | seed 의 결과를 쓰는 상위 | 1 |

총 40심볼 예산이고 ⛔ **절단분은 탐색 경계에 기록한다** — 조용한 절단은 독자에게 "이게 전부"
로 읽힌다.

## 3. 실사용 피드백이 두 번째 축을 열었다

첫 판을 쓰고 나서 결함 7건이 나왔는데 **여섯이 같은 유형**이었다 — 낯선 심볼이 정의 없이
등장한다. 순서와 범위가 맞아도 문장에 쓰인 단어를 모르면 읽히지 않는다.

축을 셋으로 재설계했다.

```
구조    무엇을 어떤 관계로 보여줄지     자체 프로토콜        G1~G6
난이도  어떤 순서로 깊어질지           progressive learning  G7
문체    한국어가 사람 글로 읽히나       외부 교정 스킬        G8
```

⛔ **참고가 알리바이가 되지 않게** 가져오는 것과 거부하는 것을 양쪽 다 적었다. level 옵션
체계와 persona 는 안 가져오고(한 문서가 세 수준을 다 담아야 한다), 문체 패턴 35종은 복제하지
않는다(두 자산이 어긋난다).

## 4. 게이트마다 근거 등급을 붙였다

H1 원칙의 BAD 사례가 "실패마다 체크리스트 행 추가 → 500개 규칙 → 68% 준수율" 이다.
그래서 게이트를 세울 때마다 물었다 — **이 게이트가 잡았을 구체적 실패를 댈 수 있는가?**

```
관측       모델 산출·독자 반응에서 확인      G4 어휘 · G5 경로 · G7 층위
사용자 요구  직접 요청·유지 요청              G6 정리 · G8 문체
[추론]     전제는 그럴듯하나 미관측          G1 인용 · G2 반사실 · G3 근거
```

⭐ 한 번은 `관측` 이라 쓸 뻔했다. 근거로 인용하려던 초안이 **사람이 쓴 글**이라 "모델이
혼자 못한다" 의 증거가 못 됐다 — 자기 규칙(G3)을 자기 문서에 적용해 등급을 낮췄다.

⚠️ `[추론]` 셋은 제거 대상이 아니라 **등급이 낮은 것**이다. 다음 사람이 관측 기반 게이트와
같은 무게로 확대하지 않도록 표기했다.

## 5. 어휘 등급 — 무엇을 설명할지 출처로 가른다

"낯선 용어를 설명하라" 는 무한 확장이다. 독자가 검색으로 못 찾는 것만 의무를 진다.

```
A  이 저장소에 정의된 심볼      정의 + 인용 필수
B  프레임워크·라이브러리 개념    한 줄 역할 + 이 프로젝트에서의 형태
C  언어·일반 개념              설명하지 않는다
```

⭐ **파생 B 의무**: A 심볼의 역할 접미사가 프레임워크 개념이면 한 심볼이 두 줄을 받는다.
`{Feature}Builder` 는 타입 정의(A)와 "Builder 가 무엇인지"(B)가 둘 다 필요하다 —
이 규칙이 없으면 사용자가 불평한 바로 그 자리에서 미달한다.

## 6. 분할선은 입력 의존 여부다

공용 모듈과 소비자 스킬을 가르는 기준 하나다.

```
공용    폐포 5축 · 어휘 등급 · 게이트 G1~G8 · 층위 · 출력 형식
스킬    seed 산출 · 슬롯 값 · 경량 변형
```

`fz-pr-digest` 의 `tutor-mode.md` 는 249 → **82줄**로 줄었고 게이트 정의 중복이 0이다.
⛔ SKILL.md 의 게이트 요약표도 지웠다 — 요약이 있으면 Lead 가 정본을 건너뛰고, 실제로
G1 기술이 정본과 어긋난 적이 있다.

⭐ 문체 절을 출력 절 **뒤에** 둔 것은 의도적이다. "문체는 구조·인용 확정 후" 라는 규칙을
글로만 쓰면 먼저 돌린다 — 배치 자체가 순서를 실어야 한다.

## 7. `fz-explain` — PR 없이 도는 설명 스킬

입력은 셋이다.

```
(a) 심볼 이름     find_symbol 직접
(b) 기능 이름     핵심 도메인 심볼을 seed 로
                 ⛔ 진입점을 seed 로 잡지 않는다 — 진입점은 R1 의 도착지다.
                    거기서 시작하면 아래로 한 홉뿐이라 흐름의 하단이 끊긴다
(c) 상황·현상     관여 심볼 역추적. 원인 진단이 아니라 동작 설명이다
```

⛔ 티켓·PR·리뷰어 개념을 갖지 않는다(`fz-peer-review` 소관). 쓰기 도구와 `Skill` 도
부여하지 않는다 — 문서 저장과 외부 스킬 호출은 Lead 몫이며, 형제 스킬 다섯 중 넷이 선언
없이 동작한다는 실측이 근거다.

## 8. fixture 를 양방향으로

⛔ positive 만 있으면 검출력만 재고 **과잉 검출은 못 잰다.**

```
positive-defects.md   결함 11종 → 게이트 8종 전수 시험
negative-clean.md     게이트를 만족하는 문서 → 오검출 0
```

첫 판은 결함이 G4·G5·G6 셋에만 몰려 나머지 다섯의 검출력을 입증하지 못했다. 숫자(7/7)는
맞았으나 의미가 달랐다.

## 9. 트리거는 추가가 아니라 재분배다

`과외` · `처음 보는 사람` · `전체 흐름` 은 pr-digest 가 아니라 explain 의 어휘다.
`설명` 단독도 뺐다 — 같은 행에 이미 `PR.*설명` 이 있어 그 스킬이 겨누는 것은 "PR 설명" 이지
"설명" 일반이 아니다.

```
전  "과외하듯 설명해줘"  →  pr-digest vs explain     경쟁 → 되묻기
후  "과외하듯 설명해줘"  →  explain 단독
    "설명해줘" 단독      →  매칭 0 → 되묻기  ⭐ 그게 정확하다
```

⛔ 빼지 않으면 새 스킬이 항상 경쟁에 걸린다. YAML 과 registry 도 동기화했다 — 두 경로가
다르게 동작하고 있었다.

## 10. Codex 교차검증 — 자체 검증 6종이 통과시킨 것들

16건 중 14건을 반영했다. 유효 건의 성격이 한 방향이다.

| 지적 | 왜 자체 검증이 못 잡았나 |
|------|----------------------|
| 같은 절의 표 vs 산문 모순 | 기계 검사는 두 표현을 대조하지 않는다 |
| G1 이 `file:line` **또는** 심볼명 | 문법이 아니라 의미다 |
| **negative fixture 가 자기 G4 를 위반** | fixture 를 입력으로만 다뤘다 |
| YAML ↔ registry 이중 소스 | lint `#4` 가 THRESHOLD 라 SKIP |

⛔ 셋째가 가장 아프다. **오라클이 오라클 노릇을 못 하는 상태**에서 "오검출 0/8" 을 선언했다.

기각 2건도 실측으로 갈랐다 — `Write` 미부여는 6개 스킬 전부 같은 형태라 fz 관례였고,
G2·G3 통합은 라벨 체계가 달라(`[기계적]` vs `[실측:N]`) 합치면 판정이 흐려진다.

## 1. 무엇이 문제였나

검사기가 **선언한 일을 하지 못한 채 통과**했다. 오류가 나지 않은 이유가 곧 결함이었다.

- 워크플로 파일은 `export const meta` + 최상위 `await`·`return` 을 가진 async 함수 본문이다. CJS·ESM 어느 문법으로도 유효하지 않아 `node --check` 는 판별력이 0 이었다(Node v26 에서 심은 문법 오류도 rc=0).
- `claude plugin validate .` 는 루트의 marketplace 매니페스트만 검증했다. plugin.json 을 대상으로 주면 YAML 파싱 실패는 오류로 잡지만, frontmatter 결손(description 누락 등)은 **경고**만 내고 exit 0 이다.
- model·effort 는 키 존재와 fable 개수만 보았고 `--baseline` 대조는 호출되지 않았다. 동시 스폰 예산·자산 census·외부 명령 검사기는 self-test 만 돌았다. 그래서 effort xhigh→high 강등이 health-check 를 통과했다. 예산 검사는 `parallelWithRetry([…])` 를 병렬로 세지 않았다.
- GPT setup 이 Claude 스킬 22개를 GPT 스킬 폴더에 링크했다. GPT 가 역할 스킬 대신 Claude 스킬을 골랐다(fz-reviewer 로드: 07-09 링크 확장 전 28세션 중 26회 → 확장 뒤 31세션 중 1회).
- plan-lean2 는 edge 렌즈가 죽어도 병합이 돌면 완주 2/2 를 보고했다. 같은 부류가 peer-review Tier 2 교차 경로에도 있었다(correctness 결손 → 완주 2/2).
- 실 PR 에서 줄인 patch 가 fixture 로 들어 있었다.

## 3. 하지 않은 것

- 사용자 `~/.codex/skills` 정리 — 사용자 환경이다. 릴리즈 뒤 setup 을 다시 돌리면 prune 된다.
- fz-review·fz-peer-review 사전 복사 순서 검사 — 두 스킬에는 아직 사전 복사(cp) 단계가 없다. S22 가 더한다. 등록 장치(`ORDER_TOKENS`)와 fz-plan 실모드만 넣었다.
- 변수로 넘긴 병렬(`parallel(lensThunks)`)의 예산 계산 — 리터럴 배열만 센다. 데이터 흐름 추적은 범위 밖이다.
- 판정기의 수면 감지(F-326) — 지금은 플러그인 밖 러너(`ab_run.py`)가 수면이 낀 run 을 원장에서 뺀다. 판정기는 아직 수면을 모른다.
- A/B run 의 MCP 격리(F-325) — 두 arm 이 같이 노출되지만 격리 목록 밖이다.
- F-317(판정기 fail-open)·F-329(고친 검사기의 거짓 통과)는 코드를 고쳤지만 실데이터 판정·재검토 전이라 닫지 않았다.
- A/B 기준선·SC-3 스모크 — 이번 측정은 러너 결함(F-332)으로 무효였다. 러너(플러그인 밖)를 stream-json 한 세션으로 고치고 기계 스모크만 확인했다. 실제 fz 워크플로 1 run 스모크 전이라 F-332 는 닫지 않았고, 기준선은 R-B 에서 다시 잰다.

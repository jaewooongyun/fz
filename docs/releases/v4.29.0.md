# v4.29.0 (2026-09-03) — 승인 도장이 남의 줄에 박혔다 [MINOR]

다섯 자리를 고쳤고, 그중 넷은 성격이 하나다. **검증 기제가 자기 대상에서 한 칸씩 벗어나
있었다** — 도장은 게이트 줄 앞으로, 문체 게이트는 자기 정본으로, evidence 는 ref 가 아닌 작업
트리로, 도구 거부는 `fallback` 으로. 넷 다 빨간불이 아니라 **엉뚱한 초록불**로 나타난다.

| 자리 | 어긋난 방향 | 겉보기 |
|---|---|---|
| `finalize()` 도장 | 시작 시점 스팬에 삽입 | 게이트가 적을 땐 통과 |
| G8 줄표 | 정본 형태를 산문으로 셈 | 정본을 지킬수록 위반 |
| `scriptPath` 거부 | `mode` 부재를 fallback 으로 | SOLO 강등이 정상처럼 |
| evidence ref | 빈 값이 작업 트리를 grep | exit 0 · "0건" |

다섯째는 Tier 2 투표 계약이다 — 벗어남이 아니라 서술이 세 갈래로 갈린 경우라 표에 넣지 않았다.
고도화 v3 착수분 5 Step(S-FIX · S0 · S2 · S3 · S4B)과 그 후속 4 다.

## `finalize()` — 도장 위치를 매 반복 재조회로 (S-FIX)

`scripts/gate_check.py` 의 `finalize()` 는 실행 게이트마다 `APPROVED_ORACLE_HASH` 한 줄을
삽입한다. 루프가 **시작 시점의 `Gate` 객체**를 계속 내고 있었다. 도장이 하나 들어갈 때마다
뒤쪽 게이트의 스팬이 1씩 밀리므로 n번째 도장은 (n−1)줄 앞에 박힌다.

한동안은 도장이 자기 블록 안에 떨어져 아무 일도 일어나지 않는다. 어느 지점을 넘어서면 게이트
줄 **앞**으로 나가 확정본이 자기 파서에 거부된다 — 게이트에 속하지 않은 속성이 있다는 파싱
오류이고 exit 3 이다. 실행 게이트 7개가 넘는 원장과 그것을 읽는 원장 검사가 함께 죽는다.

⛔ 벗어나는 **임계 공식은 여기 옮기지 않는다.** 정본은 `scripts/gate_check.py` 의
`finalize()` docstring 이고, 산문에 복제하면 정본이 한 번 바뀔 때 조용히 어긋난다 — 이번
릴리즈가 S0 에서 고친 것이 정확히 그 형태다.

id 목록으로 돌면서 매 반복 **재로드본에서** 게이트를 다시 찾는다. 사라진 id 는 통과가 아니라
`LedgerError` 다 — 도장 위치를 정할 수 없다는 것이 판정이지, 정할 것이 없다는 뜻이 아니다.

⭐ 값이 더 큰 것은 두 번째 발견이다. **`finalize` 경로를 실행하는 fixture 가 0건이었다.**
승인 계약 전체가 이 경로에서 발급되는데 그 경로를 밟는 케이스가 하나도 없었다.
`tests/fixtures/gates/finalize/eight-gates.md` 를 신설했다. 수정을 되돌리면 게이트 self-test
가 67 에서 66 으로 떨어진다 — 되돌림이 초록이면 fixture 가 없는 것과 같다.

## Tier 2 투표 계약 — 59곳 전수 감사 후 정본 지목 (S0 · S0-C)

Matrix·투표를 언급하는 자리를 전수 감사했다. 59곳이 세 갈래였다 — 정본과 같은 서술 36 ·
계약을 자기 말로 재서술 18 · 값이 어긋난 것 5.

⛔ 값을 복사해 맞추지 않았다. 뒤의 두 갈래 23곳을 **정본(§ MergeContract § 9) 지목**으로
바꿨고 값 복사는 0건이다. 값을 복사하면 정본이 한 번 바뀔 때 스물세 곳이 조용히 어긋난다 —
이번에 고친 것이 정확히 그 상태다.

감사표는 grep 과 대조해 닫았다: `grep=59 audit=59 dup=0 missing=0 extra=0`. 감사표만 있으면
"내가 세지 않은 것"을 셀 수 없다.

## G8 줄표 — 정본 형태에 한해 1개 제외 (S2)

`modules/explanation-output.md` 의 매핑 블록 정본은 담당 코드 줄을
`**담당 코드**: <경로> — <심볼>` 로 규정한다. 그 줄표는 경로와 심볼을 가르는 **구조 표시**인데
`scripts/check_g8_style.py` 는 산문 줄표와 같이 셌다. v4.28.0 이 볼드 축에서 해소한 충돌이
**줄표 축에서 되풀이**된 것이고, 블록이 늘면 줄표도 함께 는다.

담당 코드 줄 **형태**에 한해 줄표 1개를 뺀다. 둘이면 나머지 하나는 산문 줄표로 남는다 — 전량
면제가 아니다. 규약 쪽 서술은 `modules/explanation-protocol.md` 에 맞췄다.

⛔ 라벨 줄 전부에서 빼는 판이 한 번 나왔고 교차검증이 잡았다. 그러면 `**하는 일**: A — B` 같은
산문 줄표가 통째로 면제된다. **판정 축은 라벨 이름이 아니라 값의 형태다** —
`**담당 코드**: 없음 — 신규 파일` 은 그 형태가 아니므로 예외를 받지 않는다.

self-test 는 11/11 이다(신규 줄표 2건 포함).

## Workflow `scriptPath` 거부 — 우회 계약과 권한 9곳 (S3 · S3-C)

`Workflow({ scriptPath })` 가 다음으로 거부되는 경우가 있다 —
`scriptPath must be a script path this tool returned, or a file you can already read`.
⛔ **이 실패는 `mode:'fallback'` 이 아니다** — 스크립트가 아예 실행되지 않아 반환에 `mode`
자체가 없다. 그것을 fallback 으로 읽고 실패 복구 사다리를 타면 **SOLO 로 오강등**한다.
멀티에이전트 경로가 통째로 사라지는데 로그는 정상으로 보인다.

⛔ 근본 해결이 아니라 **도구별 경로 게이트**임을 먼저 적었다. 같은 경로를 `Bash`·`Read` 는
읽는다. 플러그인 루트가 세션 working directory 이거나 additional directory 면 애초에 발생하지
않는다. 계약 블록은 그 조건이 아닐 때의 세션 한정 우회이며, 조건이 사라지면 블록째 삭제한다.

우회는 4단계이고 **순서가 고정**이다 — 판별 · 의존 포함 복사 · 복사본 검증 · 재시도. 2를
건너뛰면 의존이 끊긴 복사본을 실행한다. 계약은 `guides/skill-authoring.md` 에 두고 호출 지시
10곳과 에러표 3곳에서 지목했다.

⛔ 그리고 **소비자 9곳 전부에 권한이 0이었다.** `Workflow` 를 가진 SKILL.md 아홉이
`Bash(grep *)`·`Bash(cp *)` 를 갖고 있지 않아 2·3 단계가 실행되지 못한다 — 우회가 정확히
그것이 필요한 상황에서 죽는 상태였다. 이것도 교차검증이 잡았다.

## evidence 는 ref 다 — 빈 ref fail-closed (S4B · S4B-C · S4B-D)

`modules/evidence-collection.md` 의 관례 표본 수집이 `git grep <pattern> ${BASE_REF}` 를
쓰는데 `${BASE_REF}` 가 `upstream/` 접두를 하드코딩하고 있었다. Gather 가 해석한 base 로
바꿨다 — ⛔ PR head 가 아니라 base 여야 PR 이 자기 관례의 증거가 되지 않는다.

⛔ **빈 ref 는 fail-closed 다.** 빈 값이 들어가면 `git grep` 은 **작업 트리**를 뒤지고
**exit 0** 을 낸다. 잘못된 대상에서 나온 "0건"이 정상 판정으로 읽힌다.

zsh 는 unquoted glob 을 셸이 먼저 확장하고 매칭 파일이 없으면 `no matches found` 로 **명령
실행 전에** 중단한다 — 출력이 비어 "0건"으로 읽히지만 grep 은 돌지도 않았다. 따옴표를
강제했다.

산출 종료 전 `git status --porcelain` 을 요구한다. 검증 경로가 작업 트리를 건드렸는지
산출자가 스스로 확인하는 지점이고, 이번 세션에 그 일이 실제로 일어났다(아래 § 검증자에
대하여).

## 검증자에 대하여 — Codex 불능과 대상 훼손

⛔ **마지막 두 Step 은 이종 검증을 받지 못했다.** S4B-C 이후 Codex 가 spend cap 으로 불능이
되어 fresh-context Agent(opus)로 대체했다. 같은 모델 계열이므로 blind spot 이 공유된다 —
`[fresh-context: claude]` 로 표기하고 이종 검증으로 세지 않는다.

⛔ **그 폴백 검증자가 대상을 훼손했다.** `git checkout --` 로 미커밋 변경을 삭제했고 이후
복구했다. 유실 0 은 Lead 독립 확인으로 확증했다. 원인은 명확하다 — read-only 보호가 **Codex
CLI 의 성질**이었고 대체 경로(Agent)에는 그 성질이 상속되지 않았다. 검증자를 갈아끼울 때
따라오지 않는 것은 능력이 아니라 **격리**다.

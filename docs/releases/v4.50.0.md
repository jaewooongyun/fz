# v4.50.0 (2026-11-02) — GPT 단계를 한 줄로 판정하고 재검증 라운드에 상한을 두며, 쓰이지 않는 하네스를 걷어 낸다 [MINOR]

같은 설정으로 돌려도 GPT 단계를 부를지가 스킬마다 산문으로 갈렸다(F-487). 이 판부터 모든 GPT 단계는 직전에 `gpt-choice.sh decide` 한 줄로 실행 · 생략 · 질문을 정하고, 같은 산출물을 다시 검증하는 라운드는 정문(`gpt-call.sh`)이 코드로 센다(누적 3 · 같은 입력이면 멈춤). 계획 단계의 첫 GPT 호출은 Workflow 와 함께 뜨는 독립 계획이 기본이다(끄기 `--no-gpt-independent`).
하네스 쪽은 31일 대화 기록으로 쓰이지 않은 의무(SuperClaude 세션 저장 · 복원 · sc 명령 자동 실행 · 설치되지 않은 `/ralph-loop` · 30턴 리마인더 · 노출된 옛 워크플로)를 걷고, 남긴 규칙의 근거 문단은 `references/` · `docs/rationale/` 로 옮겼다. 재발 방지 lint 7종 · 퇴역 명령 검사기 · 경로별 health-check 부분 실행을 더했다.

⛔ 새 에이전트 `arch-lens` 와 워크플로 `swarm.js` 가 생겼다 — 이 판으로 올린 뒤 **세션을 다시 시작**해야 새 에이전트가 등록된다(옛 세션에서 새 워크플로 사본을 부르면 그 렌즈가 스폰 전에 실패한다 — F-511).

## 쓰는 쪽에서 달라지는 점

- fz-fix 의 GPT check 는 GPT 를 켠 세션이면 필수다(`--gpt` 인자는 없어졌다). 끈 세션 · CLI 없음은 `[GPT 미사용 — 사유]` 로 남는다
- 같은 산출물에 GPT 검증을 네 번째로 부르면 정문이 exit 19 로 거부한다. 같은 입력이면 직전 판정 파일을 쓰라고 stderr 에 적는다 — 미해결로 보고하고 다시 돌리지 않는다
- fz-plan full 은 독립 GPT 계획을 플래그 없이 띄운다. 전처럼 끄려면 `--no-gpt-independent`
- `/fz` 새 세션 복원은 티켓 폴더 `index.md` 의 Essential Context 다. `/sc:sc-save` · `sc-load` 는 선택이다
- `--loop` · 빌드 반복 실패는 `modules/execution-modes.md` 래더와 `guides/skill-authoring.md` §12 실패 복구 사다리를 따른다
- `bash scripts/health-check.sh --changed <경로>` 는 문서 lint 와 그 경로를 읽는 러너만 돈다(출하 게이트 아님 — `--ship` 은 전체)

## 하지 않은 것

- 리뷰 GPT review 동시 기동의 실측 시작 시각 차(B10-LIVE) · 사용자 보고 계약 교체(H1-5)는 Release 2 측정으로 미뤘다
- counter 대 GPT DA 비교(M2)는 측정 인자와 어댑터까지만 — 실험은 Release 2
- 유지한 리마인더 T1~T8 은 31일 발화 0 이었다. 효과는 하나씩 빼 보기(H.4)로 잰다

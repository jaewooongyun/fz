# v4.48.0 (2026-10-19) — 무거운 경로 앞에서 light · full 을 묻고, Workflow 워커는 Lead 의 effort 로 돈다 [MINOR]

스킬을 직접 부르면 코드가 조금만 커도 Workflow(full)로 돌아 리뷰가 40~50분, 플랜이 20분 넘게 걸렸다. 이제 Workflow 를 띄우기 직전에 작업 크기로 light · full 을 추천하고 사용자가 고른다. GPT 교차 검증은 두 모드에 똑같이 붙고 끌 수 있으며, Workflow 워커는 Lead 세션의 effort 로 돈다.

Closes: F-187-team-workflow-trigger-undefined-for-direct-skill-call

## 쓰는 쪽에서 달라지는 점

- fz-review · fz-peer-review · fz-plan · fz-code · fz-fix · fz-discover 를 인자 없이 부르면 Workflow 앞에서 질문이 하나 온다. `light` · `full` 을 인자로 주면 묻지 않는다. `/fz` 경유 · 신호어("그냥" · "가볍게" 등) · 자율 모드도 묻지 않는다.
- GPT 모델 질문에서 `off` 를 고르면 그 세션의 GPT 단계를 건너뛰고 `[GPT 미사용 — 사유]` 를 남긴다. GPT CLI 가 없으면 묻지 않고 off 로 간다.
- GPT 호출 스크립트(`gpt-call.sh` · `gpt-exec.sh` · `gpt_independent.sh`)는 GPT 를 쓰지 않을 때 exit 18 과 `GPT-OFF:` 로 끝난다. 측정 실패(10~17)와 다르다.
- Lead effort 를 `xhigh` 아래로 내리면 워커도 같이 내려간다. `CLAUDE_CODE_EFFORT_LEVEL` 이 설정돼 있으면 그 값이 우선한다.

## 하지 않은 것

- 추천 임계는 초기값이다. 사용자가 고르는 구조라 실사용으로 고친다.
- light 와 full 의 품질 차이는 재지 않았다. 기본값 전환 검증은 사전등록 짝 측정 대신 실행 스모크로 재등록했다(`experiment-log.md` §5.9).
- per-call effort 가 세션 값을 이기는 것은 1회 실측했다. env · frontmatter 와의 우선순위, 세션 중 `/effort` 변경이 env 에 반영되는지는 확인하지 못했다.

# v4.51.0 (2026-11-05) — 피어 리뷰가 코멘트할 것을 고르고, 근거 · 검사 등록 · 라우팅을 기계가 잰다 [MINOR]

피어 리뷰가 후보를 거의 다 코멘트로 올리던 자리에 Curate 단계를 넣었다. 후보마다 코멘트 또는 제외(E1~E8)를 정하고, 렌더 전에 계약을 기계로 본다.
근거 슬롯 · health-check 등록 · 러너 모드 · 텔레메트리 label · 라우팅처럼 손으로 관리하다 어긋난 자리에 검사기를 붙였다. 워커 tools 의 codegraph 는 걷고, 구현 탐색은 Lead 의 Serena `find_implementations` 로 옮겼다.

> ⛔ **올린 뒤 세션을 다시 시작한다.** 에이전트 tools 에서 codegraph 를 뺐고 Serena 를 `v2.1.0` 으로 고정했다 — 둘 다 새 세션에서 반영된다.

## 쓰는 쪽에서 달라지는 점

- fz-peer-review 는 기본으로 Curate 를 돈다. 끄려면 `--no-curate` · Curate 까지만은 `--curate-only` · `--no-render` 면 Curate 도 꺼진다
- 렌더는 `--require-curation` 이 기본이다. 계약을 어기면 파일을 하나도 쓰지 않고 멈춘다
- Gather 5.5 뒤 `check_evidence_slots.py --tier` 를 부른다. `evidence/tools.md` 첫 줄에 Serena 상태를 적는다
- `evidence/caller-analysis.md` 는 `## 호출` · `## 구현` 두 절로 쓴다
- 병합본은 `merged.json` 고정 경로에 남는다 — Curate 가 후보 원본으로 읽는다
- health-check 는 러너를 병렬로 돈다. 직렬이 필요하면 `FZ_HEALTH_JOBS=1`
- 러너에 모드 플래그를 더하면 머리말에 `# modes:` 를 선언한다
- `render-single-source --default-path-unchanged` · `inject-skill-sites --base` · `--emit-sites` 는 지웠다

## 검증

Step 게이트 20/20 통과(S01~S20) · 출하 게이트(전체 health-check · 사용자 경로 증가 0) 통과 · 수동 확인 3건(새 세션 워커 tools · callers JSON 크기 · 출하 리뷰)은 사용자가 확인했다 — 원장 23/23 으로 닫았다. 저장된 synthesized 37개가 새 계약과 증상 게이트를 모두 통과했고, 실데이터 Curate fixture 는 6/6 이다.

출하 리뷰(fz-review light · GPT)가 찾은 결함 9건을 이 판에서 고쳤다 — 답글 초안이 게시 본문에 실리던 것 · challenger 경로와 Tier 1 병합본 경로 · `계속` 이 부사여도 이어 하기로 읽히던 것 · 공백 든 경로의 evidence · 큐레이션 검사 예외가 옛 산출물을 남기던 것 · 정규화가 걸러 낸 항목을 버리고 통과하던 것 · 자기 covers 의 이중 소유 오판 · swarm 로그 표기. GPT 역검증 두 차례가 부분 해결로 남긴 경계(같은 폴더의 challenger 재실행 · 독립 패스 선언 · 상태 보고와 중단 요청의 `계속` · 줄바꿈 경로)도 고쳤다 — 마지막 수정은 GPT 재검증 라운드 상한(3)에 닿아 시험 · corpus 반례로만 확인했다.

GPT 게이트 판정(verify-gates)은 23개 모두 판정했다(accept 19 · revise 4). 병렬 실행 시험을 벽시계 비교에서 동시 실행 장벽으로 바꾸고 브랜치 대상 렌더 시험을 더했다. 나머지 둘은 수동 측정 절차(callers JSON 크기)와 승인으로 고정된 게이트 본문 몫이다.

finding 레지스트리에서 엔트리가 빠지는 길은 릴리스 노트 `Closes:` 하나인데, 무엇을 적을지는 저자의 기억에 달려 있었다. v4.52.0 에서도 고친 F-550 을 빠뜨렸다. 이 판은 레지스트리의 반영 기록(`applied`)과 노트를 대조하는 `check_release_closes.py` 를 더하고, 게이트 판정기와 code-pair, 피어 리뷰에서 같은 실수를 되풀이하게 만들던 자리를 고쳤다. 문서 규칙만으로는 반복된 Phase 4 생략과 ad-hoc 에이전트 실수는 선택형 하위 플러그인 fz-guard 가 훅으로 막는다.

이 판은 finding 24건을 닫는다. 이번 판에서 고친 16건과 전에 고쳤는데 배출되지 않았던 8건이다. 일부만 고친 16건은 열어 두고, 본문이 소실된 stub 7건은 보관했다. 남은 미해소는 279건(일부 반영 16건 포함)이고 묶음별 로드맵(R1~R7)으로 넘긴다.

## 쓰는 쪽에서 달라지는 점

- 릴리스 전에 `python3 scripts/check_release_closes.py --findings-root <레지스트리> --note <노트>` 가 exit 0 이어야 한다. `applied: full` 은 전부 Closes 에 적고 partial 은 적지 않는다. `applied_ref: pending` 이 남아 있으면 막힌다
- `eject_findings.py` 는 partial 과 모르는 applied 값을 배출하지 않는다. `check_release_sync.sh --release` 는 템플릿 원문 그대로인 노트를 선언으로 세지 않는다
- 게이트 원장에 `BASELINE: required` 를 쓰면 `--baseline-probe` 없이 `--finalize` 가 되지 않는다. 기준선은 `SIDE_EFFECTS:` 를 선언한 게이트만 돌린다
- `PIN:` 을 선언한 게이트는 핀 파일이 바뀌면 재승인해야 met 이 된다. 선언하지 않은 원장의 서명은 그대로다
- `gate_check.py` 를 `--budget` 없이 부르면 예산이 대상 게이트 TIMEOUT 합까지 늘어난다
- code-pair 가 changeset 결함으로 끝나면 `reason: 'changeset-defect'` 와 `defects` 를 돌려준다. §12 L2 로 재invoke 한다
- 피어 리뷰 Curate 의 `origin` 은 regression · pre-existing · improvement 셋만 받는다
- fz-guard 는 따로 설치한다(`claude plugin install fz-guard@fz-orchestrator`). 끄려면 CLI 를 켤 때 `FZ_GUARD_DISABLE=P4,AG,FR` 또는 `all` 을 주고, 세션 중에는 파일 플래그 `~/.fz/runs/fz-guard/disable` 을 쓴다

- 커밋마다 돌리는 전체 health-check 는 이번에 건너뛰었다. 최종 트리는 전체 health-check 를 통과했고 커밋마다 부품 self-test 만 돌렸다

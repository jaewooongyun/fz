# v4.33.0 (2026-09-11) — 적용은 했는데 커밋하지 않았고, 나흘 뒤 같은 실패가 다시 왔다 [MINOR]

2026-09-06 에 수리 4건을 적용하고 AC 11개를 통과시킨 뒤 "반영됨" 이라고 레지스트리에
적었다. 커밋은 하지 않았다. 그 변경은 사라졌고 2026-09-10 에 그중 하나(base 신선도)가
**같은 증상으로 다시 관측**되고서야 유실이 드러났다.

이번 릴리즈는 그 유실분 4건을 복구하고, 같은 세션에서 새로 발견한 수리 3건을 더한다.

## 유실이 어떻게 드러났나

`/fz-peer-review` 가 PR #4853 을 수집하면서 로컬 base 가 3커밋 뒤처진 것을 잡지 못했다.
base 원본 37개 중 16개가 틀린 원본이었고, 직전 커밋에서 신설된 파일이 "이 PR 이 만든
신규 파일" 로 읽힐 뻔했다. `gh pr diff` 기준 48파일과 `git diff 로컬base...pr` 63파일이
갈려서 잡혔다 — 두 값을 대조하지 않았다면 그대로 렌즈에 배포됐다.

그 수리는 나흘 전에 이미 만들어져 있었다.

⛔ **"반영됨" 의 정의가 없었다.** 작업 트리 적용을 반영으로 적었는데 작업 트리는
휘발성이고 표기는 영속이다. 유실 경위(reset·checkout·stash)는 확정하지 못했다 —
확정된 것은 HEAD·stash·작업 트리 어디에도 없다는 사실까지다.

## 새로 고친 것

**verify-gates 제목 축약** — 원장 제목이 100~200자라 모델이 요약한다. 그러면 stale 응답으로
거부돼 7/7 이 재호출로 간다. 대조가 제목을 보는 이유는 모듈에 있었으나 그 요구가 프롬프트
쪽에 전달되지 않았다.

**gpt-exec.sh 경로** — §8 이 정본 호출 경로를 상대 경로로만 적어 스킬 base directory 로
읽으면 파일 없음에서 막힌다. 다른 모듈은 이미 `${FZ_PLUGIN_ROOT}` 를 쓰고 있었다.
⛔ 제목·목차의 파일명 언급은 바꾸지 않았다 — 헤딩을 바꾸면 앵커와 인용이 깨진다.

**risk_scan `session`** — 미니플레이어 드래그 PR 이 `session` 을 지역 변수명으로 48회 써서
auth 카테고리가 성립하고 13줄 PR 에 3렌즈+GPT 를 태울 뻔했다. 경계를 더 조여도 못 막는다 —
패턴은 이미 `\bsession\b` 이고 변수명이 정확히 그 단어다. 신뢰도를 분리해 samples 에는
남기고 risk 계수에서만 뺀다.

⭐ **실측이 계획을 정정했다.** 계획은 "동반 토큰이 다른 hunk 면 미성립" 이라 적었으나
갈리는 축은 hunk 거리가 아니라 **순증인가 개명인가** 였다. net-new auth 는 거리와 무관하게
정당한 신호이고, 개명된 auth 는 같은 hunk 일 때만 session 을 성립시킨다. 5케이스를 전부
fixture 에 고정했다.

## ⛔ 이번에 드러난 도구 문제

`set -euo pipefail` 이 이 셸에서 **발화하지 않는다.** `errexit on` 으로 보고되고 `$-` 에
`e` 가 있는데 `false; echo X` 가 X 를 인쇄한다. 시작 플래그(`bash -ec`)는 정상이다.
실제로 다단계 편집 스크립트가 죽었는데 뒤 명령이 "valid JSON · 게이트 22개" 를 인쇄해
미반영을 완료로 읽을 뻔했다. 유일하게 작동한 방어는 끝에 붙인 fail-closed assert 였다.

→ 파괴적·다단계 작업은 `bash -ec` 로 감싸거나 `&&` 연쇄 + 사후 assert 를 둔다.

# v0.59.0 (2026-11-26) — 쌓인 finding 을 이 판에서 고쳐 내보내고, 남는 엔트리에는 조건 · 기한 · 소유자를 둔다 [MINOR]

배출을 여러 번 돌려도 finding 이 남은 까닭은 '열어 둔다' 로 판정된 엔트리에 나갈 조건도 기한도 없었기 때문이다. 이 판은 엔트리마다 출구(조건 · 기한 · 소유자)를 요구하고, 쌓여 있던 관측은 검사기 · 가드 · 훅 · 문서에서 고쳤다.

닫은 finding 없음.

## 갱신하는 법

```bash
claude plugin marketplace update fz-orchestrator
claude plugin update fz@fz-orchestrator
claude plugin update fz-compact@fz-orchestrator   # 설치했을 때만 — 0.1.2
claude plugin update fz-guard@fz-orchestrator     # 설치했을 때만 — 0.6.0
```

## 주요 변경

- **finding 출구** — 위생 검사가 출구 없는 엔트리를 위반으로 센다. 기한 계산은 `deadline_of` 한 곳이고, 기한 출구 처분 `expired` 와 출구 없는 새 엔트리 거부(`--new-entry`)를 더했다
- **fz-guard 0.6.0** — PR 코멘트를 읽고 기록 없이 끝난 fz 턴을 (세션, PR) 마다 한 번 막는다. 공용 임시 폴더 글롭 `rm` · 명령 치환 안 글롭 · `--untracked` 없는 `git grep` 집계를 경고한다
- **fz-compact 0.1.2** — 훅이 답하지 못한 compaction 을 표시하고 그 세션에는 더 줄 세우지 않는다
- **게이트** — 기준선 탐침이 셸의 명령 부재 · 변수 미설정 실패를 RED 가 아니라 미실행으로 적는다. 증거 지문에 claude CLI 판을 묶는다
- **리뷰 · 피어 리뷰** — 지운 파일이 빠진 리뷰 diff 를 막는다. Tier 2/3 근거 슬롯 `open-observations` 와 Deliver 앞 테스트 기록을 요구하고, GPT 판정에 `abstain` 이 생겼다
- **출하 게이트** — 공개 노트와 CHANGELOG 의 내부 추적 번호를 거부한다. 닫은 것은 관리자 메모로 `check_release_closes.py --note` 대조한다

## 알아 둘 것

- 위생 검사 기본 모드는 출구 없는 엔트리가 하나라도 있으면 exit 1 이다 — 쓰기 전에 엔트리마다 `exit_condition:` 을 넣는다
- 진행 중인 피어 리뷰 폴더(Tier 2/3)는 `open-observations` 슬롯이 없으면 GPT 첫 패스 앞에서 exit 10 이다 — 관찰이 없으면 `evidence/skipped.md` 에 `- open-observations: 미판정 관찰 없음` 을 둔다
- A/B 원장의 도구 지문(`instrument_sha`)이 바뀌었다 — 이 판 전 실행은 다시 모은다
- `eject_findings.py` 쓰기 경로에 `--dry-run` 을 주면 거부한다(전에는 무시하고 썼다)

## 검증

출하 게이트(`scripts/check_release_sync.sh --release`) exit 0 — health-check 전체 · 커밋과 작업 트리 누수 검사 통과.

# v0.59.0 (2026-11-26) — 쌓인 finding 을 이 판에서 고쳐 내보내고, 남는 엔트리에는 조건 · 기한 · 소유자를 둔다 [MINOR]

배출을 여러 번 돌렸는데도 finding 이 남은 까닭은 판정과 배출이 따로였기 때문이다. '열어 둔다' 로 판정된 엔트리에는 나갈 조건도 기한도 없었다. 이 판은 엔트리마다 출구(조건 · 기한 · 소유자)를 요구하고, 기한이 지난 엔트리를 사람에게 묻고 내보내는 `expired` 처분을 더한다. fz-compact 는 자기 compaction 에 훅이 답하지 못한 세션을 표시하고, 그 세션에서는 더 줄 세우지 않는다.

출구만 더하면 쌓인 관측은 그대로 남는다. 그래서 이 판은 쌓여 있던 관측을 하나씩 고쳤다. 도구로 막을 수 있는 것은 검사기 · 가드 · 훅에 넣고 셀과 변이로 확인했으며, 문서로만 막을 수 있는 것은 이미 같은 실패를 다루는 문장에 한 구절씩 합쳤다.

닫은 finding 없음.

## 갱신하는 법

```bash
claude plugin marketplace update fz-orchestrator
claude plugin update fz@fz-orchestrator
claude plugin update fz-compact@fz-orchestrator   # 설치했을 때만 — 0.1.2
claude plugin update fz-guard@fz-orchestrator     # 설치했을 때만 — 0.6.0
```

## 주요 변경

- **위생 검사** — `[--strict] 출구 없는 엔트리: N` 줄을 낸다. frontmatter `exit_condition:` 이 없거나 비었거나, 기한을 계산할 수 없거나(`deadline:` 형식이 틀렸거나 시계가 없거나), `owner:` 가 빈 엔트리는 위반이다. 기한이 지난 엔트리는 `[INFO] 기한 지남` 줄로 보이고 위반으로 세지 않는다
- **기한 계산은 한 곳** — `report_stale_findings.py` 의 `deadline_of` 다. `deadline:` 이 있으면 그 날, 없으면 `last_observed:` 또는 `date:` + 90일이고, 기준일이 기한을 넘은 날부터 지난 것으로 본다. 위생 검사는 이 함수를 빌려 쓰므로 두 CLI 의 수가 같다. 날짜를 적었는데 읽을 수 없으면(달력에 없는 날 · 따옴표 · 줄 끝 `# 주석`) `last_observed:` 도 `date:` 로 물러나지 않고 판정 불가다
- **처분 값 `expired`** — `eject_findings.py --dispose expired` 가 기한 출구다. 대장 처리 값과 telemetry 배출 흐름에서 `rejected` 와 따로 센다. `--dispose` 는 대장 행 앞에 빈 줄을 더 넣지 않는다(행 사이 빈 줄이 표를 끊었다)
- **유입 제어** — `eject_findings.py --new-entry` 가 출구가 없는 초안을 쓰지 않고 거부한다(exit 1 · 사유에 빠진 요소)
- **처분 미리 보기** — `eject_findings.py` 의 쓰기 경로(`--dispose` · `--new-entry` · `--prune-index` · `--resolve-pending`)에 `--dry-run` 을 함께 주면 쓰지 않고 거부한다. 전에는 플래그를 조용히 무시하고 레지스트리를 썼다
- **재관측 절을 관측으로 센다** — 위생 apply-now 후보와 telemetry 트랙 D 후보가 엔트리 본문의 `## 재관측 … YYYY-MM-DD` 절을 관측으로 센다. 같은 실패를 새 엔트리 대신 절로 적어도 승격 계수가 줄지 않는다
- **fz-compact 0.1.2** — `guard.sh` 가 줄 선 compaction 을 막을 때 `~/.claude/fz-compact/passed-over/<세션 id>` 표지를 남긴다. `register.ts` 는 표지가 있는 세션에 더 줄 세우지 않고 한 번 알린다. 켜기 전 확인은 계정 필드 대신 평소 띄운 세션의 debug `seat` 줄이다

## 수리 — 쌓인 관측을 고쳤다

- **fz-guard 0.6.0** — fz 턴이 PR 코멘트 · 리뷰를 읽고 레지스트리 기록도 `finding 해당 없음 — <사유>` 줄도 없이 끝나면 Stop 을 (세션, PR) 마다 한 번 막는다. 명령 자리의 `gh api …/comments|reviews` · `gh pr view --comments` 만 읽기로 센다(echo · grep 인자 · heredoc 본문의 언급과 게시 호출은 세지 않는다). `/fz-peer-review` 턴은 면제하고, GitHub MCP 의 코멘트 · 리뷰 조회도 같은 규칙으로 본다. 공용 임시 폴더를 따옴표 밖 글롭으로 지우는 `rm`, 명령 치환 안의 글롭, `--untracked` 없이 개수 · 파일 목록을 내는 `git grep`(커밋하지 않은 새 파일을 빠뜨린다)을 경고한다. 읽기 전용 iOS 도구 호출(`devicectl … list` 는 json · log 출력이 없는 꼴)을 승인 전 창에서 허용한다
- **리뷰 입력** — `check_review_diff.py` 가 작업 트리에서 지운 파일이 diff 에 없으면 `MISSING-DELETED` 줄과 exit 1 을 낸다(`git add -N . ; git diff` 꼴은 삭제를 잃는다). `check_moved_code.py` 가 같은 블록을 두 곳에 더한 꼴을 표시하고, 데이터 파일(`.resolved` · `.pbxproj`)은 대조에서 뺀다
- **피어 리뷰** — Tier 2/3 근거 슬롯에 Lead 미판정 관찰(`open-observations`)을 더했다. PR 이 더하거나 고친 테스트 목록을 위험 스캔이 내고, Deliver 앞에 테스트 실행 결과 또는 미실행 사유를 요구한다. 위험 스캔은 콘텐츠 접근(등급 · 연령 · 보호자) 축과 저장소의 술어 관례 이탈을 본다. GPT 판정에 `abstain`(판정 보류)이 생겼다 — 반박하지 못했다고 agree 로 고르지 않는다. 기존 스레드 대비 독립 발견 표는 로컬 리포트에만 남고 게시 본문에는 들어가지 않는다
- **게이트 · 계측** — 종료 게이트가 통과 경로의 미측정 항목을 WARN 으로 낸다. 실행 기록이 플러그인 작업 트리의 미커밋 변경을 적는다. Stop 훅이 빠진 실행 기록을 훅 시작 10초 안에서만 알린다. 미상 쓰기 후보는 그 도구 결과가 돌아온 시각 창 안의 쓰기만 설명된 것으로 본다. A/B 원장이 실행마다 상태 · 과제 · GPT 세션 사본과 플러그인 기록을 남긴다. 적대 라운드 기록은 `--pre` 와 run-id 로 묶인다. 계획 검사가 출처 없이 정한 결정과 쓰기 범위 안의 미커밋 파일을 표시한다. 기준선 탐침(`--baseline-probe`)은 셸이 낸 명령 부재(경로 없는 이름) · 변수 미설정으로 실패한 CHECK 를 RED 기준선으로 받지 않고 미실행으로 적는다 — 아직 만들지 않은 산출물을 부르는 실패는 그대로 RED 다. 증거 지문에 claude CLI 판을 묶는다 — CLI 로 재는 항목(plugin validate · plugin test)의 결과 변화를 트리 탓으로 읽지 않는다
- **GPT 단계** — 격리 첫 패스의 검색 명령 판독이 `rg --files` · 제외 글롭 · `git grep` 을 읽는다. 세션 모델 선택지는 config 모델이 캐시 목록 밖이면 그 사실을 표시한다
- **문서** — 같은 실패를 이미 다루는 원칙 · 행 · 문단에 사례 구절을 합쳤다(lead-reasoning · cross-validation · gates · fz-code · fz-fix · fz-plan · peer-review · skill-authoring 등). 새 체크리스트 행은 더하지 않았다. 한 세션에서만 본 꼴은 후보 표기로 두었다

## 알아 둘 것

- 위생 검사 기본 모드(= `--strict`)는 출구 없는 엔트리가 하나라도 있으면 exit 1 이다. 이 판을 쓰기 전에 레지스트리 엔트리마다 `exit_condition:` 을 넣는다
- 에디터로 직접 쓴 엔트리는 `--new-entry` 거부를 거치지 않는다 — 위생 검사가 나중에 잡는다
- `report_stale_findings.py --strict` 는 기한을 판정할 수 없는 엔트리만 남으면 `STALE_NONE` 대신 `UNRUN:` · exit 2 다(stale 이 있으면 exit 1 이 이긴다)
- fz-compact 표지는 세션 id 별로 남는다. 좌석이 바뀐 뒤 그 세션에서 다시 줄 세우려면 표지를 지운다
- 진행 중인 피어 리뷰 작업 폴더(Tier 2/3)는 GPT 첫 패스 앞 근거 슬롯 검사에서 `open-observations` 가 없다고 exit 10 이 난다. 관찰이 없으면 `evidence/skipped.md` 에 `- open-observations: 미판정 관찰 없음` 한 줄을 둔다. Deliver 앞 테스트 기록이 없으면 `- test-run: <사유>` 를 같은 파일에 둔다
- 계측 도구 파일이 바뀌어 A/B 원장의 도구 지문(`instrument_sha`)이 달라졌다. 이 판 전에 모은 실행은 다시 모은다
- 출하 게이트(`check_release_sync.sh`)가 공개 노트와 CHANGELOG 의 그 판 절에 든 내부 추적 번호(`F-` + 세 자리)를 거부한다. CHANGELOG 의 finding 표도 번호를 쓰면 거부되므로 표지를 쓴다. 노트에는 `닫은 finding 없음.` 표지를 두고, 닫은 것은 관리자 메모에 적어 `check_release_closes.py --note` 로 대조한다
- 게이트 증거 지문(`env=`)에 claude CLI 판이 들어간다. 이미 찍힌 증거는 기록된 값으로 검증하므로 그대로 통과한다. 이 판부터 CLI 를 올리면 같은 게이트를 다시 돌린 증거의 지문이 달라진다
- 적대 라운드 기록 검사는 2026-11-26 부터 `--pre` 를 요구한다. 그 전 라운드는 `--pre` 없이 NOTE 와 함께 통과한다
- fz-guard 의 PR 코멘트 규칙은 `finding 해당 없음 — <사유>` 줄을 답에 쓰거나 레지스트리에 기록하면 풀린다. 끄려면 `FZ_GUARD_DISABLE` 이다

# v4.42.0 (2026-10-01) — GPT 는 Lead 가 요약한 가설을 받아 검증했고, 리뷰는 확신 없는 후보를 발견 단계에서 지웠다 [MINOR]

> R-B(품질 축)와 R-C(속도 · GPT 독립 · 기본값 전환)를 한 판으로 출하한다. R-B 만 담은 중간 v4.42.0 은 공개하지 않았다. 새 길은 전부 **옵션으로** 넣고 A/B(같은 입력 · 가린 판정)로 쟀다. **측정을 통과한 fz-peer-review 만 기본으로 켰고**, fz-review(review-live)와 fz-plan(plan-lean2)은 품질 손실은 없었지만 속도 기준을 넘지 못해 기본 off 그대로다.

## 1. 무엇이 문제였나

- **GPT 교차 검증이 독립이 아니었다.** GPT 는 Lead 가 고른 근거와 요약, 가설을 받아 리뷰와 계획을 검증했다. 같은 출처를 본 두 모델의 합의는 독립 검증이 아니다. 시간을 나눠도 격리되지 않았다 — Claude 워크플로가 도는 동안 런타임은 `~/.claude/projects` 에 로그를 쓰고 작업 폴더에는 Claude 산출물이 쌓인다. 읽기 로그로 "안 읽었다" 를 증명할 수도 없었다(S11 실측 — 읽는 대상이 명령에 드러나지 않는 실행이 있다)
- **GPT 역할 스킬이 iOS 를 전제했다(A8-03).** 역할 스킬 본문에 iOS · RIBs · SwiftUI 규칙이 박혀 있어, 다른 스택 저장소에서도 그 규칙을 프로젝트 규칙처럼 적용할 수 있었다
- **워크플로가 느렸다.** 워크플로 wall 은 직렬 스테이지 수 × 그 스테이지 최장 워커로 정해진다. 교차 워커는 응답마다 33~41K tok 를 다시 썼고, Lead 는 같은 이슈를 리포트 · 코멘트 · payload 로 세 번 옮겨 적었다
- **발견 단계가 후보를 먼저 지웠다.** peer-review 의 공통 지시문과 이슈 스키마가 렌즈에게 "confidence 80 미만은 보고하지 않는다" 를 요구했다. 게시 여부를 판정하기도 전에 개선 제안이 생성 단계에서 사라졌다
- **병합 규칙과 축 기록이 문서에만 있었다.** 렌즈와 GPT 발견의 dedup · 귀속 · 근거 확인 · 게시 등급을 Lead 가 손으로 했고, 코드 품질 축(관용 · 네이밍 · 아키텍처 규칙 · UI 구조 · 배치 · 설계 대안)을 무엇으로 봤는지 기록이 없었다. 교차 스테이지는 필수 필드를 빠뜨려 스키마 재출력을 냈다(18회 중 4회)
- **기본값을 바꿀 근거를 만들 수단이 없었다.** 옵션을 켠 효과를 같은 입력으로 비교하고 라벨을 가려 채점하는 판정기가 없었다

## 2. 무엇을 바꿨나

### 기본으로 켠 것 — fz-peer-review

| 항목 | 이전 | 지금 |
|---|---|---|

| 산출물 | 리포트 · 코멘트를 손으로 | `review.json` 하나에서 렌더 |

| craft 축 | 기록 없음 | arch 렌즈 6축 + axisCoverage |

| 교차 필수 필드 | 재출력 발생 | required 키 재고지 |

A/B 에서 품질 · 비용 · 측정 절차 기준(SC-3 · SC-4 · SC-7 · AC-1 · AC-4 · AC-5 · AC-7 · 교차 순서 · 가린 라벨)을 모두 통과했고, 시간 기준(SC-6)에서 새 경로가 238s 빨랐다(잡음 바닥 167s). `--gpt-independent` · `--render` 는 생략해도 된다. 되돌리려면 Workflow args 의 네 옵션을 끈다 — `craftAxes` · `crossRequiredFields` · `preserveLowConfidence` 는 `false`, `crossOutput` 은 `'full'`. 넷을 모두 끄고 structuralContext 에서 §6(craft 축)을 빼면 콜 입력이 기준(v4.39.1)과 바이트 단위로 같다. GPT 독립 첫 패스와 렌더는 `--no-gpt-independent` · `--no-render` 로 끈다.

### GPT 독립 첫 패스 — `scripts/gpt_independent.sh`

- **허용 입력만 격리 폴더로** 복사한다(diff · base/head 본문 · 요구 · 규칙 색인). 대상 저장소는 복사하지 않고 권한 프로필의 read 로 연다
- **읽기를 OS 수준에서 막는다** — 격리 CODEX_HOME(인증은 링크뿐 · gpt-skills 사본 · memories 끔) · 가짜 HOME(사용자 전역 스킬 폴더 차단) · 권한 프로필. 래퍼 `--config-permissions` 로 `sandbox_mode` 가 프로필의 경로 deny 를 덮지 않는다(F-348)
- **rollout 을 감사한다** — 금지 입력 · 격리 미적용 · 홈 · 루트 재귀 검색이면 exit 15(오염)로 산출을 버린다. 허용된 저장소 안의 검색은 예외다(macOS 저장소는 거의 전부 `/Users` 아래다)
- **병합과 차이표가 실패한 산출을 거부한다** — `review_merge.py` 와 `plan_divergence.py` 가 런처 옆 파일(`.contaminated` · `.audit.json`)을 읽어 오염 · 실패를 받지 않는다. 병합은 stale(감사의 diff 해시 ≠ 병합 diff)도 거부한다. 런처가 10~17 로 끝났으면 병합은 `--gpt-unavailable` 로 Claude 결과만 쓴다
- **역할 스킬 이식성** — 8개 역할 스킬이 프로젝트 규칙을 런타임에 뽑고, iOS · RIBs · SwiftUI 지식은 조건부 도메인 팩으로 옮겼다. 래퍼 `--gpt-skill-path` 는 계측 전용이고 주입은 `--inject-skill` 이다(F-335)
- **resume 교차와 정리** — fz-plan 은 `--keep-iso` 로 남긴 플래너 세션을 이어 Claude 플랜을 검증한다. 끝나면 `gpt_independent.sh cleanup --iso` 가 이름(`fz-gpt-iso.*`)과 `gpt-home/` 을 확인하고 격리 폴더를 지운다 — Lead 명령줄의 `rm -rf` 는 자동 모드가 거부했다
- fz-peer-review 는 기본이고, fz-review · fz-plan 은 `--gpt-independent` 로 켠다

- **후보 보존** — 공통 지시문의 조기 필터 문장과 이슈 스키마의 confidence 설명을 **사본에서만** `[후보 보존]` 문장으로 바꾼다. 원본 상수는 그대로라 끄면 콜 입력이 기준과 같다. 낮은 확신도 후보의 게시 등급은 병합(MergeContract §10)이 정한다
- **단일 출처 렌더** — Lead 는 판정과 문장만 `review.json` 에 쓰고 `render_review.py` 가 review-report.md · pr-comments.md · payload.json · render-preview.json 을 만든다. 줄 앵커는 `diff_anchors.py` 의 계산을 그대로 쓰고, 겹치는 hunk 는 `pick` 없이는 거부한다
- **결정론 병합** — `review_merge.py` 가 §3 키(파일 · 줄 범위 겹침 · 축)로 묶되 후보를 지우지 않는다. 근거 인용을 그 파일 hunk 에서 다시 찾아 없으면 hold 로 둔다
- **규칙 추출 · 검증** — 지침 원문 색인(`extract_project_rules.py`) → 모델별 규칙 레코드 → `check_project_rules.py --check` 통과본만 쓴다. 옵션이 아니라 fz-plan 절차 1.5 의 Lead 절차 변경이다
- **fz-plan 기계 작업** — `plan_apply_delta.py` 가 lean2 델타를 Step id 에 붙이고, `plan_divergence.py` 가 Claude ↔ GPT 독립 플랜 차이표를 만든다

## 1. 무엇이 문제였나

- **나눈 커밋이 하나씩 서지 못했다.** 기능 단위 분할을 파일 배정으로만 짜면 개수 선언이나 검사기 배선이 다른 커밋으로 가서, 커밋이 단독으로 저장소 검사를 통과하지 못한다. v4.39.0 은 10커밋 중 5개가 그랬다. v4.40.0 도 첫 분할안이 G3 에서 같은 원인(`scripts/` 선언 42 ≠ 실측 43)으로 깨졌다 — 이번에는 커밋 전 격리 검증이 잡았다
- **리허설 PASS 가 규칙을 되풀이했다.** 이력 재작성 1차 리허설은 "규칙을 적용한 원본 == 결과" 로 판정해 PASS 였지만, 규칙에 없던 소문자 티켓 키 · ref 이름 · 손으로 바꾼 파일명이 양쪽에 똑같이 남아 있었다. 리허설 명령은 최종 명령의 태그 분기를 타지 않았다
- **공개 표면을 도구 기준으로 셌다.** 재작성이 닿는 git 객체만 셌고, 릴리스 본문 34개 · 새 커밋의 신원 · 옛 이력을 쥔 로컬 ref 는 계획 밖이었다
- **노트를 마지막 게이트 뒤에 고쳤다.** v4.39.0 노트를 게이트 재실행 뒤에 줄여 템플릿 게이트가 깨진 채 발행됐다

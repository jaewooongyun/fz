## 배경 — 왜 하나의 릴리즈인가

v4.21.0(2026-07-09) 발행 이후 약 한 달간 작업이 커밋으로만 누적되고 발행되지 않았다. 그 사이 CHANGELOG에는 `[4.23.0]`·`[4.24.0]`·`[4.25.0]` 세 개의 번호 붙은 섹션과 `[Unreleased]` 8개가 쌓였다. 그 번호들은 **origin·태그·GitHub Release 어디에도 존재한 적이 없다** [verified: `gh release list` Latest = v4.21.0 · `git ls-remote --tags origin | grep v4.2[0-9]` → v4.20.0/v4.21.0뿐].

따라서 초안 번호 4.23.0~4.25.0을 폐기하고 **누적분 전체를 v4.22.0 하나로 발행**한다. 근거:

- 미발행 구간에 `[MAJOR]` 0건 — 전부 MINOR/PATCH → 합산해도 MINOR 1회 = `4.21.0 → 4.22.0`이 semver 정합
- 4.23/4.24/4.25 문자열은 `plugin.json`·`marketplace.json` 2곳에만 존재. 스킬·모듈·가이드·워크플로·훅·스크립트 참조 0건 → 번호 정리가 다른 계약을 깨지 않는다
- 하향(4.25.0 → 4.22.0)을 관측하는 소비자가 없다. 마켓플레이스 소스는 GitHub repo이고 그 최신은 4.21.0 — 외부에서는 `4.21.0 → 4.22.0` 전진만 보인다

## 1. fz-rebase 스킬 신설 — 리베이스 조용한 유실 게이트

기존 검증 게이트는 **히스토리의 형태**(커밋 수 / 머지 수 / base 조상 / tree clean)만 검사해 "개수 보존 = 내용 보존"을 암묵 전제했다. 실제 유실은 대부분 **개수가 그대로인 채** 발생한다. 게이트를 **형태 → 내용 → 원격** 3층으로 재구성했다.

### 1-a. 1차안 — 유실 유형 열거 (폐기)

조용한 유실 6종(L1~L6)을 git 2.50.1 man page 원문과 함께 명문화하고, 유형별로 판정하는 게이트를 만들었다.

- **L1** 커밋 통째 드롭 — `--empty=drop` 기본 + *"commits which are clean cherry-picks ... are detected and dropped as a preliminary step"*
- **L2** 머지 커밋의 수동 해결 소실 — **머지 개수가 보존**되어 종전 게이트를 전부 통과했다(완전 사각지대). app-iOS develop 최근 머지 20개 중 1건이 `--remerge-diff` 15줄 = 실존 리스크
- **L3** 팀원의 이동/삭제로 내 hunk가 옛 경로에 dead code로 잔존
- **L4** 충돌 해결 방향 역전 — *"the sides are swapped"*
- **L5** 무충돌 clean 적용으로 생성물/전체 재작성 커밋이 base 최신을 되돌림
- **L6** ff-pull **이후** 팀원 push → `--force-with-lease`가 통과하면서 팀원 커밋만 파괴

`scripts/verify-rebase.sh` 서브커맨드 3종(`snapshot`/`audit`/`prepush`)과 `scripts/test-gates.sh`(7/7 PASS) 신설. 정본을 `range-diff` → 라인 보존 불변식으로 교체(`range-diff`는 선형 시리즈를 전제해 **머지 커밋을 순회에서 제외**[실측: 8커밋(머지 1) → 7행]).

**부수 수정**: `check`가 key-path 미전달에서 `key_paths[@]: unbound variable`로 **macOS 기본 bash 3.2.57에서 항상 exit 1** — 게이트가 있다고 믿는 상태였다.

### 1-b. 최종안 — 경로 단위 배타 분할

요구는 "하나도 누락 및 덮어씌임 없게"였다. **열거는 빠뜨린 유형을 증명하지 못한다** — 실제로 세 축이 검증 밖에 있었다. 판정 근거를 열거에서 **구조**로 바꿨다.

세 트리(PRE·BASE·POST) 경로 합집합을 세 버킷으로 나누고 각각 불변식을 둔다:

- **① MINE-only**(내가 변경 & base 미변경) → POST가 **PRE와 바이트 동일**(mode 포함)
- **② not MINE**(내가 미변경) → POST가 **BASE와 바이트 동일**. 다르면 팀원 변경 덮어쓰기 또는 무관 파일 오염
- **③ OVERLAP**(양쪽 변경) → 텍스트는 라인 4방향, 바이너리는 **WARN**(라인 판정 불가 → 사람 확인)

결과: **텍스트·바이너리·mode·symlink·gitlink·추가·삭제·이동**이 열거 없이 판정 범위에 든다. 커버리지 **13/15**, 비대상 2건 명시(커밋 메타데이터 · 워킹트리 dirty/stash).

- ⛔ **`git cherry`는 머지 커밋을 보고하지 않는다** [실측: 원격 3커밋(머지 1) → `+` 2건, 머지 subject 0건] → 1차안 `prepush`는 **팀원의 머지 커밋 파괴를 놓쳤다**. 2단 판정 신설: 수동 해결을 품은 머지=**HALT** / 평범한 PR 머지=**WARN**
- ⛔ **바이너리 268/3,214(8.3%)가 라인 검사 밖이었다** [실측 app-iOS]. blob 비교가 이 8.3%를 판정 범위로 들여온다
- ⛔ **롤백 앵커의 덮어씌임 수정**: 1차안은 리베이스 전 해시를 상태파일 1곳에만 뒀다 → `snapshot` 재실행이 이전 앵커를 덮어썼다. `refs/fz-rebase/pre/<branch>-<shorthash>` ref로 남긴다
- ⛔ **자체 결함 1건 — awk `NR==FNR` 함정**: 첫 파일이 비면 `NR==FNR`이 두 번째 파일 전체에서도 참이 되어 **출력이 통째로 사라진다**. rename이 없는 리베이스(=대다수)에서 `mine` 집합이 빈 채 "위반 없음"으로 통과했다. 3곳을 `FILENAME==ARGV[1]`로 교체
- **성능** [실측 커밋 142·변경 300파일]: `snapshot` 7.0s → **0.4s**, `audit` 10.4s → **0.4s**
- **회귀 스위트 20 assertion**(7→20, **20/20 PASS**): 유실 검출 10 + **오경보 방지 10**
- **미측정(명시)**: OVERLAP 방향②·④의 false-positive 율

## 2. fz-peer-review — 인라인 라인 앵커 게시 + 발견 서술 원칙

### 2-a. 인라인 게시 경로 신설

`--post`가 PR 대화창 단일 코멘트만 달아, 리포트에 file:line을 적어도 리뷰어가 직접 파일을 열어 찾아가야 했다. 코드 라인 옆(Files changed)에 붙이는 경로를 추가한다.

- **`scripts/diff_anchors.py`**: 지적 구간의 앵커 가능 여부 판정. 겹치는 hunk는 **모두 반환하고 선택은 Lead에게 남긴다** — 어느 hunk가 논지인지는 의미 판단이라 스크립트가 고를 수 없다. side(RIGHT/LEFT) 지원, `diff --git` 경계 상태 머신, Git quoted path 해제. ⛔ **Python stdlib 전용** — `ac8-link-check.sh`가 rg 하드 의존으로 미설치 환경에서 exit 127인 전례를 반복하지 않는다
- **`modules/peer-review-inline-anchoring.md`**: 게시 7단계 + 조건부 확인 게이트 + 다지점 분할(SSOT). 다중 라인은 `start_side` 짝 필수(누락 시 422), 착지 검증은 `review_id` 범위로 한정
- **`references/fixtures/pr4655-sample.patch`**: PR #4655 축약본(3파일 26hunk). 플러그인 안에 둬야 외부 폴더 정리에 테스트가 깨지지 않는다
- `Bash(gh *)`는 21개 스킬 중 이 스킬만 선언한다 — `mcp__github__create_pull_request_review`의 `comments[]`에 `start_line`·`side`가 없어 범위 하이라이트와 LEFT 앵커가 불가능하기 때문

### 2-b. 발견 서술 원칙 모듈

`review-report.md` 계약이 필드 7개 + 글자수 제한 2개였는데, 결함마다 인과의 모양이 달라 서술형 발견을 담지 못했다. 부정 주장("~할 방법이 없다")은 후보를 소진해야 증명되고, 순서 의존 결함은 경우를 전개해야 한다.

- **`modules/peer-review-finding-anatomy.md`**: 원칙 3 + 형태 예시 4종(소진 증명표 / 경우 전개표 / 확정·조건부 2분할 / 대안 성격 라벨). ⛔ 예시는 게이트가 아니다 — 과잉 형식화 방어 절을 함께 둔다
- SKILL 필수 필드 9개 → 6개. 에이전트 JSON 스키마는 dedup·투표를 위해 균일해야 하므로 그대로 두고, **Lead가 사람에게 설명하는 자리에만** 원칙을 적용한다

### 2-c. 문서↔코드 계약 정합

SKILL.md·tiers.md·에이전트 정의가 `workflows/peer-review.js`의 실제 반환·모델과 어긋나 있었다.

- **`counter` 키는 존재하지 않는다** — DA 산출은 `strengthChallenges`로 오는데 소비 절차가 없어, `--deep`이 청구하는 Stage3 결과가 **버려지고 있었다** → 소비 규칙 명시
- `agent_status` 보정은 **도달 불가한 죽은 절** — 스키마에 필드 자체가 없고 failed 제외는 `.filter(Boolean)`이 이미 한다 → 결측 에이전트 처리로 대체
- **1-review 경로 신설** — 스크립트는 전부 null일 때만 fallback을 반환하므로 1개만 성공하는 경우가 실재하는데 계약이 없었다(투표 불가 → confidence ×0.7)
- Tier 표 모델 열이 sonnet인데 **실제 호출은 전부 opus 3** → 스크립트를 single source로 명시. 비용 상한 수치는 무효 → 기본 call 수로 대체
- Tier 2/3 본문이 TeamCreate·SendMessage를 "필수"로 지시해 SKILL Boundaries와 **정면 충돌** → Workflow 시퀀스로 교체
- oracle 일반화: "View 변경 감지" → "판별 방법(oracle) 명시" (런타임 순서는 DEBUG 로그, 서버 계약은 curl)

## 4. 계측·lint 도구

### 4-a. 문서 최신성 lint 신설 (P1)

전수 감사 결과 `last audited` 보유 파일이 **105개 중 4개**뿐 — fz가 자기 문서의 stale을 탐지할 수단이 없었다. 탐지를 사람 주의력에서 분리한다.

- **대상 한정**: 외부 URL 인용 문서 **22개**만. 내부 근거만 인용하는 문서는 외부가 바뀌어도 stale해지지 않는다
- `fz-modernize` Phase 2 배선 — **기존 수동 grep 2건을 흡수·삭제**(DELETE/MERGE-default 준수)
- 결과: audit 날짜 보유 **4 → 12 / 22**, `stale-model-ref` **1 → 0**. 잔여 10건은 의도된 백로그
- **언어 선택 근거**: bash 아닌 Python — `verify-rebase.sh`가 macOS bash 3.2 empty-array nounset으로 crash한 전례

### 4-b. 제약 부하 floor/ceiling 분리 계측 (P2)

감사에서 "fz-plan hot-path 45,808 tok"이 나왔으나, 도구가 스스로 *"참조는 UPPER BOUND"* 라고 명시해 **발견으로 보고할 수 없었다**.

- **3-버킷 분류 신설**: `catalog` / `citation` / `load`. floor·ceiling은 `load` 버킷만 집계
- **floor(무조건) vs ceiling(로드 전체) 분리** — floor = 그 스킬을 부르면 **항상** 드는 비용
- **`--refs <skill>` 감사 모드 신설**: 휴리스틱을 **반증 가능하게** 만드는 것이 목적 — 이 모드가 오분류 3종을 전부 잡았다
- **확정 결과**: `fz-plan` **45,808 → floor 13,694**(3.3배 축소). 단 **`fz` 자신이 floor 31,259로 최고** → "제약 총량" 우려는 기각이 아니라 **대상이 이동**
- ⛔ 잔여 한계는 **전부 floor 과대평가 방향(안전측)**. COST ≠ REMOVAL-SAFETY
- ⚠️ **계측 한계(T1)**: `skills/*/SKILL.md`만 스캔 → `agents/`(13개)·`modules/` 상호 참조 미집계

# v4.45.0 (2026-10-10) — 원장 · Stop 훅 · 계측기가 한데 뭉쳐 읽던 상태를 나눴다 [MINOR]

fz 개선 계획(2026-10-07)의 세 판 가운데 둘째 판(R-E2)이다. 게이트 원장과 Stop 훅, A/B 계측기가 서로 다른 상태를 하나로 읽던 자리가 있었다. 승인만 되고 착수 전인 원장을 미완 작업으로, 판정기로 원장을 고친 세션을 남으로, 결과가 오지 않은 advisor 호출을 0 으로, 실패한 시도와 재개한 시도를 한 run 으로, 단어 등장 수를 질문의 답으로 읽었다. 이 판은 그 상태들을 따로 센다. 고친 곳마다 같은 검사를 기준 트리(v4.44.0)와 후보 트리에 함께 돌려, 기준에서는 실패하고 후보에서는 통과하는지 확인했다.

## 쓰는 쪽에서 달라지는 점

- fz-plan 이 원장을 확정하면 `STATE: planned` 로 둔다. 착수는 fz-code 의 `--set-state active` 다. planned 원장에서는 CHECK 실행과 `--confirm` 을 막는다.
- 판정기 쓰기 호출만 한 세션(fz-code · fz-review 등)도 자기 원장이 미충족이면 Stop 훅에 막힌다. `--status` 만 부른 세션은 막히지 않는다.
- `--only <게이트>` 는 충족 게이트도 다시 돌린다. 오래 걸리는 게이트는 그만큼 걸리고, 재실행이 FAIL 하면 그 게이트는 미충족으로 내려간다. 상태만 보려면 `--status --only` 를 쓴다.
- `--discover` 요약에 '착수 전 N' 과 '미판정 N' 이 붙는다. 종료 코드는 그대로다.
- Stop 훅은 `~/` 로 시작하는 원장 인자, `if` · `while` · `until` 조건, `{ …; }` · `timeout` 래퍼 뒤의 판정기 호출을 아직 보지 않는다(`modules/gates.md` 잔존 위험).
- `ab_ledger.py` 행에서 `retries` 별칭이 없어졌다. `tool_errors` 를 읽는다.
- `fz_wf_metrics.py` 출력에 `advisor_calls` · `advisor_stalled` · `failed_attempts` 등이 늘었고, stage 키는 `workflowName` 기준이다. 운용 규칙 5(`modules/governance.md`)는 `advisor_stalled` 도 본다.
- 스킬의 Workflow 호출은 매번 WORK_DIR 로 복사하고 `cmp` 로 대조한다. allowed-tools 에 `Bash(cmp *)` 가 들어갔다.
- impact resolver 의 RESOLVED 는 '질문형으로 판별되지 않은 요청' 이다. 판별이 어휘 규칙이라 Lead 는 RESOLVED 도 요청 문장과 census 를 훑는다.

# v4.41.0 (2026-09-27) — 원장은 미룸을 포기로만 적을 수 있었고, 확정 원장을 고치는 길은 자기 거부 문구에 막혀 있었다 [MINOR]

> R-B 실행 선행. 세 릴리스(R-A·R-B·R-C)에 걸친 계획을 게이트 원장 하나로 끌고 가면서 R-A 내내 우회로 버틴 원장 도구의 구멍과, 실패 판별 표에 빠져 있던 상태 하나를 채운다. R-B 본 작업은 v4.42.0 이다.

Closes: F-328-stop-hook-blocks-later-release-gates, F-334-gate-ledger-cannot-add-gate-to-approved-ledger, F-338-gate-selftest-fixture-args-resolved-against-cwd

## 1. 무엇이 문제였나

- **뒤 릴리스 게이트를 표현할 수단이 ABANDON(포기)뿐이었다.** 원장 하나가 세 릴리스에 걸치는데, R-A 를 진행하는 동안 Stop hook 은 R-B·R-C 게이트까지 미충족으로 세어 매 Stop 을 막았다. ABANDON 으로 적으면 수용 기준이 사라졌다는 거짓 기록이 된다 (F-328)
- **확정 원장을 고치는 길이 자기 거부에 막혔다.** 확정 원장에 도장 없는 게이트가 있으면 읽기를 거부하는데, 거부 문구가 권하는 `--finalize` 도 같은 읽기에서 막혔다. 남은 우회는 `APPROVED:` 헤더를 지우고 전부 다시 도장을 찍는 것뿐이라, 다른 게이트의 계약 변경까지 함께 재승인될 수 있었다 (F-334)
- **`ALL MET` 이 재실행을 뜻하지 않았다.** 기본 실행은 이미 충족된 게이트를 다시 돌리지 않는데, 출력에 그 사실이 없었다. 대상 코드를 고친 뒤 `--only` 로 "다시 돌려" `ALL MET` 을 받았지만 명령은 실행되지 않았다. 강제 재실행 `--reverify` 는 원래 있었다 — 관측 당시 짐작한 이름(`rerun`·`force`)으로 찾아 부재로 읽었다 (F-330)
- **self-test 가 플러그인 루트에서만 초록이었다.** verdict 케이스 11개가 fixture 경로를 루트 기준 상대 경로로 넘겼고, 그 경로가 호출 위치 기준으로 풀렸다. 루트 밖에서 돌리면 11개가 파일을 못 찾아 exit 2 로 FAIL 했다. health-check 는 `cd "$ROOT"` 뒤에 self-test 를 돌려서 이 결함을 볼 수 없었다 (F-338)
- **실패 판별 표가 렌즈 결손을 몰랐다.** 렌즈 하나가 죽어도 반환 형태는 정상(`mode:'workflow'`)이라 표의 어느 행에도 걸리지 않았다. 알리는 필드는 워크플로마다 다르다 — `plan-lean2.js` 는 `degraded` · `missingLenses`, `code-pair.js` 는 `reviewVerdict:'partial'` 이다

## 2. 무엇을 고쳤나

| 항목 | 이전 | 이후 |
|---|---|---|
| 미룸 (F-328) | ABANDON 뿐 | `CURRENT_RELEASE` + `DEFER` |
| 확정 보강 (F-334) | 헤더 삭제 뒤 전체 재도장 | `--finalize --only <ids>` |
| 재실행 표시 (F-330) | `ALL MET` 만 | 도장만 확인한 게이트를 `MET` 줄로 |
| self-test (F-338) | 루트 밖 11 FAIL | 호출 위치와 무관 |
| 판별 표 (§12) | 6종 | 7종 (렌즈 결손) |

- **미룸** — 원장 머리에 `CURRENT_RELEASE: <릴리스>` 를 두고, 미룰 게이트마다 `DEFER: <게이트ID> <릴리스> <이유>` 를 적는다. 릴리스가 CURRENT_RELEASE 와 다른 DEFER 게이트는 `deferred` 로 세고 미충족에서 뺀다. 같아지면 DEFER 는 효력이 없어 평소처럼 판정한다. CURRENT_RELEASE 없는 DEFER, 한 게이트에 DEFER 와 ABANDON 을 함께 쓴 것, 형식 오류·중복·없는 게이트는 원장 읽기를 거부한다(exit 3). deferred 게이트가 남아 있으면 `--set-state closed` 를 거부한다 — DEFER 는 출구가 아니다
- **확정 보강** — `--finalize --only <ids>` 는 확정 원장에서만 받는다. 적은 게이트에만 승인 도장을 찍고, 나머지 실행 게이트는 도장이 현재 계약과 같을 때만 통과시킨다. 계약이 바뀐 게이트가 있으면 거부한다 — 바꾼 게이트를 재승인하려면 `--only` 에 명시한다. 도장 없는 게이트가 있을 때의 거부 문구도 이 명령을 권하도록 바꿨다
- **재실행 표시** — 기본 실행은 도장만 확인한 게이트를 `MET   <id>: 기록된 증거 — 다시 돌리지 않았다(재실행은 --reverify)` 로 인쇄하고, 요약에 `reran` · `stamp-only` 수를 붙인다. `--reverify --only <id>` 는 그 게이트 하나만 다시 돌린다
- **self-test** — manifest 의 `tests/fixtures/gates/…` 인자를 sandbox 사본 경로로 옮긴다(원장은 이미 sandbox 사본을 쓴다). health-check 는 이제 self-test 를 루트 밖(`${TMPDIR:-/tmp}`)에서 돌린다
- **판별 표** — `guides/skill-authoring.md` §12 에 6행 렌즈 결손을 넣었다. 완주로 세지 않고 L3 1회 뒤 L4 로 간다. code-pair 의 `partial` 은 `skills/fz-code/SKILL.md` 반환 처리 6(재invoke 여부를 Lead 가 판정)을 따른다. `check_failure_table.py` 가 7종을 세고, self-test 변형은 행 번호가 아니라 상태 이름으로 찾는다 — 번호로 찾으면 행 하나를 끼울 때 변형이 원문과 같아져 헛돈다

## 3. 하지 않은 것

- **F-330 의 stale 판정** — 충족 게이트가 읽는 파일이 바뀌었는지는 여전히 판정하지 않는다. 이번 판은 "다시 돌리지 않았다" 를 보이게 하고 재실행 명령을 안내할 뿐이어서, 오라클(`--only` 에서 stale 을 보고하거나 다시 실행한다)을 글자 그대로 충족하지 않는다. 그래서 F-330 은 닫지 않는다
- **렌즈 결손 처방의 통일** — `plan-lean2` 는 L3 뒤 L4(사용자)로, `code-pair` 는 Lead 판정으로 간다. 맞출지는 R-B 계획 개정에서 정한다
- **R-B 본 작업** — 이 판은 실행 선행만 담는다

## ⚠️ 업데이트 순서

이전 판(v4.40.1 이하)의 `gate_check.py` 는 `DEFER:` · `CURRENT_RELEASE:` 줄을 오류 없이 무시하고, 미룬 게이트를 미충족으로 센다. 원장에 DEFER 를 쓰기 전에 이 판으로 업데이트한다 — 그러지 않으면 Stop hook 이 계속 뒤 릴리스 게이트에서 막는다.

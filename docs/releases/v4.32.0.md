## H1 — 접두를 바꾸는 게 아니라 접두 가정을 지운다

사용자 지시는 "ASD 티켓은 없어, TVG 로 바뀐지 한참됐어" 였다. 이것을 치환 과제로 읽으면 틀린다. 플러그인은
**배포물**이고, `TICKET_PREFIX|티켓 접두|ticket prefix` 어휘가 저장소 전체에 0건이었다. 접두가 낡은 것이
문제가 아니라 **사용자 한 명의 Jira 접두를 하드코딩한 것 자체가 결함**이다. 그래서 판정은 일반화다.

- **코드 계약**: `\b(?!PR-)[A-Z]{2,6}-\d{2,5}(?![A-Za-z0-9_])` [verified: `skills/fz-manage/scripts/parse_memory.py:108`]
- **어휘 계약 6슬롯**: `ASD 폴더` → `티켓 폴더` · `ASD 활성` → `티켓 폴더(WORK_DIR) 활성` · `비ASD` →
  `비-티켓 세션` · `ASD-xxxx` → `{TICKET}`(예시 ID = `TVG-1234`) · `ASD-\d+` → `[A-Z]{2,6}-\d{2,5}` ·
  절차 명사 = `Work Dir Pre-flight`
- **기본 레이아웃**: `ASD-0000/gates` → `TICKET-0000/gates` [verified: `scripts/gate_stop_hook.py:304`].
  이 문자열은 실제 디렉토리 생성에 쓰이므로 접두 중립이어야 한다

### ⭐ 후행 경계 한 글자가 하위호환을 가른다

워커가 낸 초안은 `(?!\w)` 였다. Python 의 `\w` 는 유니코드 기본값에서 **한글 음절을 매치**하므로 `TVG-4442를`
같은 조사 부착형이 통째로 비매치가 된다 — 새 접두만의 문제가 아니라 기존 `ASD` 표기에도 똑같이 적용되는
**하위호환 손실**이다. Lead 판정으로 `(?![A-Za-z0-9_])` 까지만 좁혔다. ASCII 접미(`TVG-12suffix`)는 여전히
걸러지고, 조사·문장부호가 뒤에 붙은 형태는 살아남는다.

워커 초안은 이 케이스를 NOTE(판정 없음)로 유보했다 — 정규식이 바뀐 뒤에도 "재측정 필요" 만 찍는 상태였다.
fixture 케이스 10 으로 승격해 `ASD-1234에서`·`TVG-4442를` 의 매치를 단언한다. 릴리즈 노트 초안이 이 유보를
"green 아님" 으로 정직하게 적었고, 그 지적이 fixture 의 빈자리를 드러냈다.

### ⛔ 잔존 grep 은 표현 드리프트를 못 잡는다

워커 둘이 같은 슬롯을 서로 다르게 썼다 — `티켓 폴더 Pre-flight`(4파일) vs `Work Dir Pre-flight`(3파일).
두 표현 모두 `grep ASD → 0` 을 통과한다. AC 가 재는 것은 **잔존 개수**인데 실제로 깨지는 것은 **표현의 단일성**
이었다. `guides/skill-authoring.md:431` 의 작성 체크리스트가 헤딩 문자열을 이름으로 검사하기 때문에 1종이어야
한다. Phase 0 은 티켓 부재 시 NOTASK·Serena fallback 도 포함하므로 `Work Dir Pre-flight` 로 정규화했다
(17건). 이후 AC 는 표현 분포 grep 이다.

판정이 갈릴 수 있던 자리 하나는 문면 치환을 거부했다 — `modules/promotion-ledger.md:417` 은 "`D-1` 이
`ASD-1234` 에 **부분 매치**한다" 는 문장이라, 접두만 바꾸면 `TVG-1234` 안에 `D-1` 이 없어 **문장이 거짓이 된다.**
같은 파일에서 실제로 성립하는 짝 `L-1` ⊂ `L-10` 으로 재앵커했다.

애초에 이 Step 이 조건부 모듈 형태로만 살아남은 것도 측정기를 읽고 나서였다 — `measure_constraint_load.py`

## 계측·정정 3건

- **§8.2 adjust 축** — 스테이지 load-bearing 판정에 `adjust` 를 넣었다. overturn 0~1 **AND** adjust 0~1 일
  때만 A/B 후보이고, 0~1 은 **잠정 휴리스틱**으로 표시했다. 실측 peer-review `cross`(N=20 · overturn 1 ·
  adjust 41)는 후보 *제외* 근거가 아니라 후속 검증 대상이다 — `adjust` 는 schema 가 `newSeverity` 를 필수로
  요구하지 않아 건수가 유효 조정과 1:1 이 아니다. "카운트는 판정 건수이지 옳음이 아니다" 경계는 그대로 뒀다.

  ⛔ 두 플래그는 codex 에 **전달하지 않는다**(기록 전용) — 대상 예시 9개가 raw `codex exec` 라 wrapper 전용

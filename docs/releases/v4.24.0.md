## 1. codex 교차검증 복구 — 네 경로가 죽어 있었다

`scripts/codex-exec.sh`가 `-C`와 `--add-dir`를 모드 무관 공용 인자 배열에 넣고 `codex exec review`에 넘겼다. review 서브커맨드는 두 플래그를 받지 않는다. **review·check·final·commit 네 경로가 전부 exit 2**로 끝났고, 비정상 종료라 "이슈 0건"으로 오독될 위험이 상시였다.

두 서브커맨드 `--help`를 전수 대조하니 exec 전용이 9개였고 wrapper가 넘기던 것 중 정확히 둘이 걸렸다. `-o`도 거부될까 검토했으나 review help 69행에 실재해 기각했다.

- 공용 배열에는 양쪽 수용 플래그만 남기고 둘을 exec 전용 `EXEC_ARGS`로 분리
- review는 서브셸 `cd "$CD"`로 작업 디렉토리 확보 (호출자 cwd 불변)
- review + `--add-dir` 조합을 exit 10으로 거부하는 사전 게이트 추가
- 신규 `scripts/check-codex-flags.sh` — 한 플래그가 아니라 **집합**을 검사한다. `-C`만 고치면 `--add-dir`가 남기 때문이다

**오라클**: `codex exec review` 실호출 exit 0 + 산출 JSON 801B. fixture는 정상 0 / 회귀 2종 각각 1.

## 2. fail-open 카운터 5곳

`grep -c … || echo 0`은 0매치에서 두 줄(`0` + `0`)을 만들어 정수 비교를 죽인다. `modules/peer-review-tiers.md:102`가 여기 걸려 **risk escalation이 무발화**했다. 실패가 아니라 낮은 Tier가 정상처럼 보이는 형태다.

5곳을 `|| true`로 치환했다. 이 관용구는 저장소 4곳에 이미 있었다 — 정답이 안에 있는데 전파되지 않은 경우다.

**오라클**: 텍스트 부재가 아니라 행동으로 판정 — 빈 입력에서 단일 정수 산출 + 비교 성립.

## 3. Negative-Result Gate 배선 복구

`git grep -nE '\bSym\b'`가 ERE `\b` 미지원으로 에러 없이 0건을 냈고, 그 "잔존 소비자 0건"이 세 렌즈 전원에게 배포될 뻔했다. 렌즈는 Bash가 없어 재측정이 불가능하므로 cross-model 검증이 cross-data가 아니게 된다.

⛔ **원 진단이 틀렸다.** 게이트 신설을 제안했으나 `modules/cross-validation.md` §Negative-Result Gate가 이미 있었다(`8a3b576`, 2026-08-10). 게다가 **6곳에서 트리거된다** — `lead-reasoning:183` · `system-reminders:24` · `fz-discover:231` · `fz-search:343` · `fz-manage:178,195`. **fz-peer-review에만 연결이 없었다.**

- Gather §4 Fact 검증에 항목 4 신설 — 0건·부재가 결론인 Fact는 게이트 적용
- Deliver 트리거에 병기 (Coverage Gate만 지목하고 있었다)
- 함정 표 2행 — `git grep`의 `\b` · 파일명으로 심볼 grep

배선 위치를 Synthesize가 아니라 **Gather**로 잡았다. 거짓 0건은 세 렌즈에 배포되기 *전*에 막아야 한다.

## 4. 위임 프로세스의 쓰기 · MCP 인코딩

**cwd 오염**: `--cd`로 준 디렉토리는 위임 프로세스의 쓰기 대상이기도 하다. 팀 워크트리를 넘긴 호출이 산출물 17개를 남긴 실측이 있다. `fz-codex-bash-hygiene.md` §8 사후 게이트 표에 1행 추가 — 호출 전후 `git status --porcelain` 대조. 결과가 아니라 부작용을 보므로 exit을 바꾸지 않고 경고만 낸다.

**MCP 비ASCII**: 파라미터는 UTF-8을 그대로 받는다. `\uXXXX` 수동 변환은 안전장치가 아니라 오류원이었다 — 5천 자 한국어를 그렇게 보냈더니 **응답 200인데 본문 11곳 손상**. 이 층에는 빌드도 린트도 없다. `skill-authoring.md` §12 규약을 외부 시스템 전송 축으로 확장했다.

## 5. findings ↔ ledger 진입 절차 + 트랙 D

`promotion-ledger.md`와 `memory-guide.md`에서 fz-findings를 찾으면 **0건**이었다(같은 파일이 다른 자산은 17회 참조). 발견을 쌓는 큐와 승격을 판정하는 원장이 서로를 모른 채 각자 대기열을 늘렸다.

원장에 § fz-findings 진입을 신설하고 엔트리 성격 A~E의 귀속을 정의했다. 코드 버그와 배선 누락은 원장을 거치지 않고, 구현 마찰은 트랙 A, 외부 catch는 트랙 C로 간다.

E 성격(하네스 결함·측정 실패·판정 오류·게이트 위음성)은 기존 4트랙 어디에도 맞지 않아 **트랙 D를 신설**했다. 승격 조건은 별개 세션 2건 + 회귀 fixture 1개 + 외부 채점 1회다. fixture를 넣은 근거는 원장 실측에서 **활성 차단 사유 1위가 fixture 부재(3건)** 였기 때문이다. ⚠️ 임계값은 인접 트랙과 맞춘 잠정값이며 승격 3건 누적 시 재검토한다.

**P-track 재평가에서 5건 중 3건이 이미 구현돼 있었다.** 승격 절차와 실제 구현 경로가 분리돼 있어 구현이 먼저 되어도 원장은 "관측 대기"로 남는다. 구현 3건 종결 · 미구현 2건 REMOVED로 관측 대상이 6항목에서 1항목이 됐다.

## 6. fz-rebase 게이트 무음 실패

홀을 격리 fixture로 실증했고 **넷 중 둘이 게이트 자신의 무음 실패**였다.

- `git merge-base`가 공통 조상을 못 찾으면 `set -euo pipefail` 아래에서 출력 없이 종료 → meta.env 부재로 내용 게이트가 통째로 비활성화. `die`로 전환
- OVERLAP 검사가 `git grep -h`로 파일명을 버려, 같은 문자열이 다른 곳에 있으면 유실이 통과. 경로 인덱스 + 2단 판정(트리에도 없으면 HALT / 이 파일에만 없으면 WARN + 목적지)
- 머지 해결 대조를 subject·줄수에서 **해결 내용 해시**로 — 서로 다른 두 evil merge가 subject·줄수 모두 동일한 실측이 있었다
- base 신선도를 `ls-remote`로 대조, prepush에서 롤백 앵커 잔존 경고
- ref 인젝션 차단 — git은 ref 이름에 `$(...)`·백틱·`|`를 허용한다. `source`를 걷어내고 셸 해석 없는 파서로 교체
- 오라클 20 → 65. `assert()`가 exit code만 봐서 새 WARN 경로가 기존 20건 전부에 invisible이었다

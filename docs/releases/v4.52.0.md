# v4.52.0 (2026-11-07) — 식은 bg 세션을 모델 호출 없이 줄이는 fz-compact 를 더하고 비용 집계를 바로잡았다 [MINOR]

선택형 하위 플러그인 fz-compact 를 더했다. bg 세션이 프롬프트 캐시 1시간을 넘겨 쉬면 오래된 큰 도구 결과를 파일로 옮기고 경로를 담은 자리표시자로 바꾼다. 요약 모델은 부르지 않는다. 텔레메트리 리포터는 캐시 쓰기를 5분과 1시간 단가로 나눠 계산하고 advisor 를 따로 센다.

## 무엇이 바뀌었나

| 영역 | 이전 | 이후 |
|---|---|---|
| 식은 bg 세션 | 복귀하면 전체 문맥을 캐시 쓰기로 다시 낸다 | 쉬는 동안 큰 결과를 파일로 옮긴다 |
| bg 세션 재개 | 엔진이 원문을 되살린다 | 같은 자리표시자로 다시 가린다 |
| 사람의 `/compact` | 지시문 그대로 | 보존 지침을 덧붙인다 |
| 캐시 쓰기 비용 | 모두 1시간 단가로 가정 | 5분, 1시간 분해대로 계산하고 분해 없는 몫만 `assumed_1h` |
| advisor 비용 | 메인 비용에 없고 호출 수를 덜 셌다 | 블록 id 로 호출을 세고 따로 표로 낸다 |
| 단가 표 | Sonnet 5.5, Haiku 5.5 없음 | 추가 |
| compact 정책 문구 | 발동을 최대한 늦추라고 읽혔다 | 덜 채워 발동 자체를 줄인다 |
| 검사 범위 | fz 본체만 | health-check 에 fz-compact 세 줄, pre-commit 에 `mods/` |
| 릴리스 동기 검사 | fz 본체 버전만 | 하위 플러그인 버전 동기와 바뀐 뒤 버전 올림까지 |

## 쓰는 쪽에서 달라지는 점

- fz-compact 는 따로 설치하고(`claude plugin install fz-compact@fz-orchestrator`) userConfig `enabled` 를 `true` 로 켜야 돈다
- 마스킹은 bg 세션에서만 돈다. 지시문 덧붙이기와 spill 파일 Read 허용은 세션 종류와 상관없다
- 기본값으로는 61분 넘게 쉬고 컨텍스트가 200K 토큰 이상이며, 순절감이 대화의 20% 와 50K 토큰 둘 다 이상일 때만 건다. 설정 키 10개는 `mods/fz-compact/CLAUDE.md` 에 있다
- 최근 사람 프롬프트 6개 구간은 가리지 않는다. 백그라운드 작업 알림처럼 엔진이 넣는 행은 이 6개에 세지 않는다
- 원문은 `~/.claude/fz-compact/spill` 아래에 30일 남는다. 묻지 않고 허용하는 Read 는 manifest 에 기록된 spill 파일뿐이다
- Team, Enterprise 조직 계정에서는 내장 보안 플러그인이 compact 훅을 건너뛰게 해서 마스킹하지 않는다. 그때는 안전 훅이 엔진 요약을 막고 쉴 때마다 skip 알림이 한 줄 남는다
- 텔레메트리 리포트의 비용이 이전 판과 다를 수 있다. 5분 쓰기를 더 싼 단가로 계산하고 advisor 를 따로 더하기 때문이다

## 하지 않은 것

- 조직 계정에서 우회부터 안전 훅까지 이어지는 전 구간은 실세션으로 확인하지 않았다. 안전 훅의 차단과 통과는 개인 계정 bg 세션에서 확인했다. 보안 플러그인이 앉았는지 미리 알아내는 장치도 없다
- compaction 마다 엔진이 붙이는 SessionStart 훅 첨부는 걷지 못한다. 측정한 환경에서는 재개마다 약 4.5K 토큰씩 늘었다
- 리뷰 뒤에 고친 다섯 자리(재개의 200K 기준, 절감률 분모, Read 허용 범위, 재개 면제의 확인 표시, 엔진 행 제외)는 단위 시험과 돌연변이로만 확인했고 실세션으로 다시 돌리지 않았다
- 엔진 행은 transcript 에서 실측한 행 머리 마커 5종으로 거른다. 엔진 계약이 아니라서 형식이 바뀌면 보호 구간이 다시 좁아진다
- 재개 재마스킹을 줄 세우는 판정은 확인 표시가 없는 항목도 센다. 그 항목은 검사를 다시 받으므로 검사 없이 가려지지는 않는다
- 자동 compact 문턱 A/B 판정과 그 뒤 단계는 다음 판이다

## 검증

fz-compact plugin test 55건과 안전 훅 시험 16건, `check_release_sync.sh` self-test 9건이 통과하고 health-check 와 `check_release_sync.sh --release` 가 exit 0 이다. 원장의 릴리스 대상 게이트 15건이 모두 met 이고, 실제 세션 10회(bg 9, `-p` 1)로 유휴 마스킹, 재개, 권한, 경합, 끄기, 안전 훅을 확인했다. GPT 교차 검증 지적 10건(check 8, review 2)과 역검증이 부분 해소로 본 1건, Lead 가 찾은 3건을 모두 고쳤고, 고친 자리마다 되돌리면 해당 시험이 실패하는 것을 돌연변이로 확인했다.

<summary>근거 — 교차 검증으로 고친 것</summary>

- 정리가 공유 spill 폴더의 남의 UUID 이름 폴더까지 지웠다. 읽을 수 있는 manifest 가 있는 세션으로 좁혔다
- spill 이 일부 실패한 뒤 절감을 다시 재지 않았다. 성공한 새 결과만으로 다시 잰다
- 같은 이름 파일을 다시 쓸 때 세션 용량을 두 번 셌다. 바뀐 파일 크기를 뺀다
- 따뜻하게 재개한 세션에 유휴 타이머가 걸리지 않았다. 남은 시간으로 다시 건다
- 시작 정리가 같은 시작의 재마스킹이 다시 쓰는 지금 세션 파일을 지울 수 있었다. 지금 세션은 건너뛴다
- 재검사가 통째로 바뀌지 않는 행의 결과까지 절감으로 셌다. 실제로 바뀌는 행의 결과만 센다
- 쓰이지 않은 spill 항목이 manifest 에 남아 다음 재개에서 절감 검사를 면제받았다. 면제는 확인 표시가 있는 항목으로만 좁혀, 기록이 실패하면 검사를 다시 받는다
- 식은 재개가 처음 가리는 결과에 `idleMinTokens` 를 보지 않았다. 재개에도 같은 기준을 건다
- 절감률의 분모에 도구 호출 인자가 빠져 있었다. 인자를 JSON 길이로 더한다
- spill 루트 아래라면 어떤 파일이든 묻지 않고 Read 를 허용했다. manifest 가 이름을 댄 spill 파일만 허용한다
- 백그라운드 작업 알림처럼 엔진이 넣는 user 행을 사람 프롬프트로 세어 보호 구간이 좁아졌다. 그런 행은 세지 않는다
- `check_release_sync.sh` 가 하위 플러그인 버전을 보지 않았다. marketplace 항목과의 동기, 직전 태그 뒤 바뀌었을 때의 버전 올림을 본다. self-test 픽스처의 git 도우미가 서브셸 안에서만 정의돼 기존 시험 하나가 다른 이유로 통과하던 것도 고쳤다

# v4.26.0 — peer-review 의 병목은 fan-out 이 아니었다 [MINOR]

`/fz-peer-review` 가 오래 걸리는데 품질이 그만큼 오르지 않는다는 문제에서 출발했다.
진단이 짚은 것은 예상과 달랐다 — 느린 원인과 품질이 안 오르는 원인이 **서로 달랐고**,
느린 쪽은 에이전트를 많이 써서가 아니었다.

## 이 릴리즈의 성격

시간 축과 품질 축을 따로 고친다.

**시간** — Lead 가 혼자 순차로 하던 Gather 를 배치 스크립트로 옮겼다. 실측 약 20분 → **2초**.
**품질** — 판정 규칙을 계약으로 세우고, 경량 경로가 그 계약을 우회하던 배선을 막았다.

⛔ Workflow 자체는 줄이지 않았다. 실측 결과 그쪽은 낭비가 아니었다 —
콜 수에 비례하고, 늘어난 2콜이 신규 발견 4건과 동료 교정 3건을 냈다.

## 1. 병목 측정 — `agent_calls=0` 인데 분 단위였다

`experiment-log.md` §5.7 에 fz-peer-review 테이블이 없었다. SKILL.md 가
"metrics 는 §5.7 에 기록" 이라 지시하는데 **대상이 존재하지 않았다.**

테이블을 만들고 과거 실행 10건을 백필했다. 반박 불가능한 단서 하나가 나왔다 —
**에이전트를 하나도 스폰하지 않은 실행도 분 단위가 걸렸다.** wall-clock 의 바닥은
병렬 구조가 아니라 Lead 의 순차 작업이다.

파일 mtime 으로 한 실행(51분)의 구간을 복원했다:

| 구간 | 시간 | 일하는 주체 |
|---|---|---|
| Gather | 약 20분 | Lead 단독 |
| 3-렌즈 Workflow | 757초(12.6분) | 3-병렬 |
| Synthesize·Deliver | 약 15분 | Lead 단독 |

⚠️ mtime 은 구간을 **상한으로 묶을 뿐** 전부가 능동 작업이었음을 증명하지 않는다 —
턴 사이 대기가 섞여 있다. 그래도 **35분가량에 Lead 외에 일하는 주체가 없다**는 사실은 남는다.

근본 원인은 도구 권한 설계다. 렌즈는 Bash·`git show` 에 접근할 수 없고(Workflow 워커는
`acceptEdits` 강제 — `tools:` 제거가 유일한 방어), 그래서 Orchestrator 가 코드를 미리 모아
데이터로 넘겨야 한다. 병렬화가 아니라 **Lead 쪽 호출 횟수**를 줄이는 것이 남은 레버였다.

## 2. Gather 를 배치 스크립트로

결정론 구간을 한 번에 끝낸다. `gather.sh` 가 diff·요구사항·base 원본·변경 규모·위험 판정을
한 호출로 만든다 — 실측 **2~4초**.

⚠️ 스크립트는 **원재료까지만** 만든다. `old-new-pairs`·`caller-analysis`·`convention-samples`
같이 판단이 필요한 수집은 Lead 몫으로 남긴다.

### exit 계약

| exit | 뜻 | 산출물 |
|:---:|---|---|
| 0 | 성공 | 전부 |
| 2·3·4 | 사용법 · 대상 해석 실패 · 수집 실패 | **없음** (staging 경유) |
| **5** | **base 원본 전건 실패** | **남긴다** |

⛔ exit 5 를 나눈 이유: diff 는 유효하고 origin 근거만 없다. 2·3·4 처럼 지우면 diff 까지 버린다.
진행 여부는 Lead 판단이고, 진행하면 전 issue 의 `origin` 을 `미지정` 으로 둔다.

## 3. 위험 판정 — 오탐이 Tier 를 올리고 있었다

한 리뷰에서 위험 4건이 매칭됐는데 **전부 오탐**이었다. `actor` 가 `Interactor` 에 걸렸고
전부 hunk 헤더였다. 자동 판정대로였으면 114줄 PR 이 상위 Tier 로 올라가 3~6 콜을 유발한다.

`risk_scan.py` 로 이관하며 네 가지를 바꿨다:

| 축 | 이전 | 현행 |
|---|---|---|
| 대상 | diff 전체 | **추가된 코드 라인만** |
| 경계 | 없음 | 토큰 경계 — 단, 카테고리마다 정책이 다르다 |
| 단위 | 매칭 행 수 | **카테고리 수** |
| 기준 | 추가 라인 존재 | **net 증가** (토큰별) |

⛔ 경계 정책을 카테고리마다 다르게 둔 이유: 오탐 축과 정탐 축이 **다른 단어에 있다.**
`actor` 는 식별자 내부 등장이 오탐이지만 `auth` 는 식별자 내부 등장이 **정탐**이다
(`authManager`·`tokenProvider`). 일괄 `\b` 를 걸었더니 정탐 3건이 함께 죽었다.

net 판정은 개명·이동을 걸러낸다. 실측 — 코드 이동 PR 이 `task {` 4:4 · `@MainActor` 6:6 처럼
**모든 토큰이 정확히 균형**인데 구 로직은 risk=2 로 세어 +2 승격했다.

⚠️ 토큰 단위로 센 이유: 카테고리 합계로 세면 같은 카테고리 안의 **치환**을 놓친다
(`-await` / `+Task {` 는 합계 1:1). 다만 실제 PR 7건에서 카테고리 단위와 판정이 갈린 경우는
**0건**이다 — 엄격히 더 정확하나 증분 가치는 미측정이다.

## 4. Workflow 의 조용한 판정 결함 넷

빌드도 테스트도 못 잡는 자리들이다. 값이 틀리는 게 아니라 **판정이 틀린다**.

**Stage 2 조건부 실행** — 렌즈가 합의했는데도 교차 조정 2콜이 무조건 돌았다.
severity 불일치·단독 major 를 세어 발화할 때만 돈다.
`stage2Ran` 은 하드코딩 `true` 였다 — 가드에 걸려 0콜이어도 `true` 를 반환해
"조용한 off 방어" 라는 목적을 정면으로 배반했다.

**correctness 를 교차 입력에** — 트리거는 correctness 를 포함해 계산하는데 교차 대상은
arch↔quality 뿐이었다. correctness 의 단독 major 가 opus 2콜을 유발하고도 `unreviewed` 로
남았다. 입력만 늘리므로 call 수는 그대로다.

**범위 파싱** — `41, 293-295` 를 min-max 로 뭉치면 41–295 가 되어 사이의 무관한 finding 이
전부 "같은 자리" 가 된다. 그리고 `line_range` 는 스키마상 optional 이라 위치 미상 major
하나가 무조건 교차를 발화시켰다 — 판단 불가는 단독이 아니다.

**교차 병합의 덮어쓰기** — correctness issue 는 양쪽에서 판정받는데 `map[id]=a` 가
뒤에 온 렌즈로 앞을 지웠고 **concat 순서가 결과를 정했다.** 갈리면 고르지 않는다 —
Tier 2 는 투표하지 않으므로 `contested` 로 유보하고 원본 판정 둘을 보존한다.

## 5. 계약 3종 — 판정이 즉흥 판단에 기대고 있었다

한 실행에서 Lead 가 문서에 없는 `[L실측] 우선` 규칙을 그 자리에서 만들어 썼다.
최종 14건 중 5건이 문서화되지 않은 판단에 기댔다. 계약의 목적은 그 5건을 죽이는 게 아니라
**정식 경로로 살리는 것**이다.

| 계약 | 무엇을 보장하나 |
|---|---|
| **C1 MergeContract** | 입력원 · 렌즈 상태(`skipped` ≠ `failed`) · dedup 키 · Lead 실측의 자격 · Codex verdict · confidence 산식 |
| **C2 DiscoveryContract** | 9 perspectives → 5축 매핑 + 축별 집계. `direction` 은 owner 가 없어 "0건 = 탐색 안 함" 을 표기 |
| **C3 InputHygiene** | Lead 의 가설이 판정 근거로 되돌아오지 않는다 |

⛔ C1 에서 `reverse` 는 **제거가 아니라 `question` 전환**이다. 자동 제거로 만들면
이종 검증이 삭제 권한을 갖고, 코드로 결판나지 않는 사안이 조용히 사라진다.

⛔ C3 의 관측 근거: Lead 가 영향 범위 후보를 목록으로 적자 렌즈 둘이 **같은 목록을
되돌려줬다.** 3렌즈 합의처럼 보이지만 독립 확증이 아니다.

## 6. ⛔ 경량 경로가 게이트를 통째로 우회하고 있었다

이 릴리즈에서 가장 값이 큰 발견이다.

Coverage Gate 는 `SKILL.md` 의 `### 4. Confidence Matrix 출력` 안에 있다.
그런데 Tier 0 은 그 Matrix 를 **"대신 simple checklist"** 로 건너뛴다.
**게이트가 경량 경로가 지나가지 않는 자리에 붙어 있었다.**

`peer-review-tiers.md`(Tier 0/1 절차 정본) 참조 수 실측:

| 게이트 | 참조 |
|---|---:|
| Coverage Gate | **0** |
| Negative-Result Gate | **0** |
| InputHygiene | **0** |
| Reflection Rate | **0** |

형제 4스킬(`fz-plan`·`fz-review`·`fz-code`·`fz-modernize`)은 이미
"light 에서도 **생략 불가** (검증 경계)" 를 쓰고 있었다 — 발명이 아니라 복사였다.

`peer-review-gates.md` 에 경로별 생존 표를 두고 Tier 0/1 절차에서 참조한다.
⛔ **"미적용"과 "생략"을 구분한다** — 전자는 설계(Tier 0 에 Confidence Matrix 가 없는 것),
후자는 누락이다. "미수행" 으로 뭉뚱그리면 읽는 사람이 판별할 수 없다.

## 7. lint 2종 — 같은 클래스가 반복해서 열린다

### `#N11` 경량 경로 검증 계약 선언

게이트 5건 중 지적받은 1건만 고쳐졌다(1/5). 사람 주의로는 클래스가 안 닫힌다.
경량 경로를 가진 스킬은 **그 경로 절차가 있는 문서**에 계약을 선언해야 한다 —
⛔ 절차를 모듈로 위임하면 그 모듈에도 있어야 한다.

⛔ 배선보다 **먼저** 만들었다. 나중에 만들면 처음부터 green 이라 무엇을 잡는지 알 수 없다.

### diff 파서 hunk 상태 선언

같은 결함이 네 번 났다 — `+`·`-`·`+++`·`---` 는 hunk **안팎에서 뜻이 다른데**
상태 없이 접두사만 보면 행을 잃고 파일 귀속까지 엉킨다.

⛔ 정답은 같은 디렉터리에 이미 있었다(`header_done`·`inhdr`). 옆 파일 둘이 이미 방어했는데
새로 쓴 셋이 각자 다시 틀렸다.

변수명을 검사하지 않는다 — 실제 이름이 `inhdr`·`header_done`·`h`·`in_hunk` 로 다 다르고,
첫 탐지기가 그중 하나를 몰라 오탐을 냈다. **선언**을 요구하면 새 파서를 쓰는 사람이
세 갈래 중 하나를 고르게 되고, 고르려면 함정을 읽게 된다.

⚠️ 선언은 주장이다. `.md` 안의 인라인 bash 는 대상이 아니다 —
"위반 0건" 을 전수로 읽지 말 것.

## 8. 리뷰 표면 진단 — diff 가 부풀려져 있었다

`diff` 는 merge-base 기준이다. base 가 분기 후 앞서 나가면 **이미 base 에 있는 변경**이
다시 나타난다.

실측: base 가 39커밋 앞서 있었고 head 3커밋 중 2개가 이미 base 에 있어
diff 가 26파일 +304/−182 로 보였으나 실제 리뷰 표면은 **18파일 +83/−83** 이었다 — 2.9배.
Tier 도 486줄로 계산돼 한 단계 위를 골랐다.

`git cherry` 로 중복 커밋을 지목해 `review-surface.md` 에 적는다.
⛔ **자동 보정하지 않는다.** GitHub 은 merge-base 기준 전체를 보여주므로 스크립트가
조용히 범위를 줄이면 리뷰어 간 범위가 어긋난다.

## 9. 이동 리팩토링 — 동등성 통과가 "이동 완료"를 뜻하지 않는다

파일 분리 PR 에서 추가·삭제 라인을 정규화해 다중집합으로 빼면 이동 여부가 확정된다.
한 PR 에서 423/393 중 차이가 38건뿐이었고 전부 헤더·import·접근수준이었다 —
값 표현식 변화 0.

그런데 그 데이터를 통과한 뒤에도 3렌즈가 `origin: regression` 3건을 찾았다.

| 발견 | 내용 |
|---|---|
| 헤더 드리프트 | 새 파일 헤더가 "선언·구현·상태 모두" 라는데 그 파일에 프로토콜 선언 0건 |
| 이중 선언 유지비 | 조건부 컴파일로 선언이 두 벌이 된다 |
| 기능 분산 | 분리 후 기능이 5개 지점에 흩어진다 |

셋 다 이동이 만든 것이고 동등성 데이터에는 나타나지 않는다.
**동등성과 드리프트는 다른 축이다.**

`move_drift.py` 가 세 축을 데이터로 만든다. 관점을 늘리지 않은 이유 —
관점 추가는 모든 리뷰의 비용을 올리지만 evidence 는 이동 PR 에서만 발동한다.

⛔ 판정 대상은 `git cherry` 의 `+` 커밋분이다. 첫 조건식이 개명 PR 을 "이동" 으로 잡았는데,
그 신규 파일은 **이미 base 에 머지된 중복 커밋분**이었다 — 오탐의 원인은 조건식이 아니라 입력이었다.

## 10. 실측 기록

`experiment-log.md` §5.7 에 12행. 1~10 은 백필이고 11~12 가 개선본 실측이다.

⛔ 없는 값은 추정하지 않고 `unavailable` 로 둔다 — 추정치를 실측 자리에 넣으면
baseline 구실을 못 한다.

경로 분포: Tier 0 ×3 · 1 ×4 · 2 ×4 · 3 ×1. **경량 경로가 58%** 이고
그중 3건은 사용자가 '경량' 을 명시 요청했다 — auto-tier 의 부산물이 아니라 반복 선택되는 경로다.

⛔ **확산 임계는 여전히 판정 불가다.** 사전등록은 `3건 전수` + 경로별 최소 1건 +
paired replay 를 요구하는데 개선 후 실행 2건이 둘 다 `agentCalls 0` 이다.

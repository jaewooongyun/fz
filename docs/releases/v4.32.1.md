# v4.32.1 (2026-09-08) — 모델은 gpt 인데 문서는 실행 파일 이름을 부르고 있었고, 게이트는 여섯 번 조용히 통과했다 [PATCH]

2026-09-06 에 `fz-codex` 스킬을 `fz-gpt` 로 개명했다(72파일 · 357치환). 그런데 사용자가
세션에서 여전히 `codex` 표기를 봤다. 이번 사이클은 그 잔재를 전수 실측해 옮긴 것이고,
**활성 810 occurrence 중 546 을 옮기고 268 을 보존했다** — 84파일 482 insertions / 482 deletions.

## 두 층위를 구분하지 못했다

`~/.codex/config.toml` 의 `model` 은 `gpt-6-astra` 다. 교차검증을 실제로 수행하는 모델은
GPT 이고, `codex` 는 그 모델을 호출하는 **실행 파일 이름**(`/opt/homebrew/bin/codex`,
`codex-cli 0.153.4`)이다. 문서가 이 둘을 뭉뚱그려 모델의 판단을 도구 이름으로 부르고 있었다.

`3중 검증 (Claude + Codex + sc:analyze)` 의 Codex 는 모델이 하는 일이고, `Codex 가 대화형
입력을 기대해 무한 hang` 의 Codex 는 CLI 의 동작이다. 앞은 GPT 가 정확하고 뒤는 codex 가
정확하다. 판정 축은 하나로 고정했다 — **그 자리의 이름을 바꾸면 벤더 계약(바이너리·경로·
플래그·플러그인 네임스페이스·intent trigger)이 깨지는가, 아니면 사실이 거짓이 되는가.**

⛔ **`gpt` 라는 명령은 이미 존재한다.** `/usr/sbin/gpt` 는 GUID partition table maintenance
utility 다. `codex exec` 를 `gpt exec` 로 바꾸면 `command not found` 로 실패하는 게 아니라
**디스크 파티션 도구가 실행된다.** 조용히 다른 프로그램이 도는 쪽이 에러보다 나쁘다.

## 보존의 근거를 세어 보지 않았다

첫 판정은 치환 130 · 보존 680 이었다. 사용자가 "애초에 codex 를 안 쓰고 gpt 모델을 쓰는데
왜 codex 를 남기냐" 고 물었고, 재실측 결과 **보존 판정 대부분에 근거가 없었다.** "실행되는
도구가 Codex CLI 이므로 GPT 로 바꾸면 부정확해진다" 는 근거 하나를 458건에 일괄 적용했는데,
그 근거는 CLI 동작을 서술하는 12건에만 참이었다.

판정을 뒤집었다 — **기본값이 MOVE 이고 KEEP 이 예외다.** 보존 근거는 둘뿐이다.

보존한 것 11종: `codex exec`·`codex review` 명령(119) · `Codex CLI` 제품명(42) · `~/.codex/`

## 게이트가 여섯 번 조용히 통과했다

⭐ 이 사이클에서 가장 값이 큰 것은 치환 자체가 아니라 **무성 실패 6건**이다. 전부 정상
종료 + 빈 결과였고, 검증 없이 넘어갔으면 도구가 깨졌다.

| # | 증상 | 원인 |
|---|------|------|
| 1 | `codex $1 --help` → `gpt $1` (파티션 도구 실행) | 규칙이 리터럴 서브커맨드만 매치, 변수 인자를 놓쳤다 |
| 2 | `codex 0.144.1` → `gpt 0.144.1` | CLI 동작 규칙이 대문자 `Codex` 만 매치했다 |
| 3 | `codex→gpt 개명` → `gpt→gpt` | 개명 이력 서술 보호 규칙이 없었다 |
| 4 | 사후 게이트가 유출 3종을 놓침 | **`git grep -E` 는 `\b` 를 지원하지 않는다** — 정규식이 조용히 0건을 낸다 |
| 5 | 게이트가 정상 표기를 오탐 | 패턴이 과도하게 넓어 `/fz-gpt review`·`gpt-5.5` 를 잡았다 |
| 6 | 치환 1건 유실 | positive control 주입을 `git checkout` 으로 지울 때 정당한 변경도 함께 사라졌다 |

4번은 게이트 **자신**의 실패라 나머지 다섯을 전부 통과시켰을 것이다. positive control 이
그것을 잡았다. 같은 클래스로 zsh unquoted `$VAR` 의 비-단어분할, ugrep 의 한글 조사
alternation, Python `\w` 가 한글을 매치해 `Codex CLI가` 에서 후행 `\b` 가 성립하지 않는 문제,
`assert` 없는 replace 의 무성 실패도 이 세션에서 만났다.

## 이종 모델이 규칙 밖을 봤다

Claude 자체 검증 4층(분류기 · 역방향 KEEP 검증 · 사후 유출 게이트 · health-check)이 전부
통과한 뒤 GPT 교차검증이 **3건을 더 잡았고 전부 실측으로 확정됐다.**

- **벤더 공식 URL 이 깨져 있었다** — `developers.openai.com/codex/cli` → `/gpt/cli`. 규칙에
  URL 보호 축이 아예 없었고 사후 게이트에도 URL 검사가 없었다. 복원 후 **URL 집합 불변
  검사**를 배선했다(제거·추가 URL 집합이 달라지면 실패).
- **출처 태그가 재포장됐다** — `[외부: Codex review …]` → `[외부: GPT review …]`. 정규식은
  정확했으나 **occurrence 판정 window ±60자**를 넘는 긴 태그의 닫는 `]` 가 범위를 벗어나
  매치가 실패했다. 해당 규칙을 라인 전체 스캔으로 바꿨다.
- **현행 기록 스키마가 누락됐다** — `experiment-log.md` 의 `codex_unique_findings`. 그 파일을
  통째로 아카이브로 판정했는데 과거 기록과 현행 스키마 정의가 섞여 있었다.

4층이 모두 "내가 세운 규칙" 을 검사하므로 규칙 자체의 공백은 그 안에서 보이지 않는다.

## 검증

`git archive HEAD` 로 원본을 추출해 **검사 대상 건수를 전후 대조**했다. 통과 여부만 보면
"검사가 정상 돌면서 대상만 비어 있는" 실패를 놓친다.

```

#N9 cross-file 섹션     173 → 173        #N3 줄번호 인용      44 →  44

보존 7종 개수 감소 0 — codex exec 123 · Codex CLI 60 · ~/.codex/ 30 · .codex/skills 21
                       codex mcp 7 · Bash(codex 6 · codex --version 3

```

`bash -n` 은 문법만 보므로 `GPT_EXIT` 경로는 실제 호출로 검증했다.

## ⚠️ 알려진 breaking change 가능성

`## Codex Skills` → `## GPT Skills` 는 내부 5곳(grep 패턴 · 서술 3 · 템플릿)이 일관되게
바뀌었다. 그러나 **프로젝트 CLAUDE.md 에 옛 제목을 쓰는 사용자**는 Tier 1 디스커버리가

영향은 0이었다. 옛 제목도 호환 입력으로 읽는 것은 후속 안건이다.

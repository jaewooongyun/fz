# 설명 출력 구조

> `modules/explanation-protocol.md` §7 의 본문. 층위별 섹션 A~E 의 형식을 정한다.
> ⛔ 규칙(폐포·어휘·게이트)은 정본에 있다 — 여기는 **형식만** 담는다.

## 참조 스킬

| 스킬 | 참조 이유 |
|------|----------|
| fz-explain | 설명 문서의 섹션 형식 |
| fz-pr-digest | Tutor 티어가 같은 형식을 공유 |


⛔ 마크다운 파일로 끝낸다. 다른 출력 형식은 이 모듈의 범위 밖이다.

### A. 기능 전체 흐름 (층 0~1)

진입점부터 소비자까지 제어가 흐르는 순서대로 서술하고 각 단계에 담당 파일을 병기한다.

```markdown
## 목차

- [A. 기능 전체 흐름 (층 0~1)](#a-기능-전체-흐름-층-01)
- [B. 등장하는 것 (층 1)](#b-등장하는-것-층-1)
- [C. 동작↔코드 1:1 매핑 (층 2)](#c-동작코드-11-매핑-층-2)
- [D. 구조 근거 (층 3)](#d-구조-근거-층-3)
- [E. 탐색 경계 (부록)](#e-탐색-경계-부록)

---

## 이 기능은 어떻게 동작하나

1. 사용자가 {동작}을 한다
   → `Path/EntryFile.ext:45` `onTapHandler`
2. {다음 단계}
   → `Path/Middle.ext:120` `SymbolName`
...
N. {최종 결과가 반영된다}
   → `Path/Sink.ext:33`

{호출 스킬이 정한 좌표 표시 — 예: 이번 변경이 닿은 지점}
```

### B. 등장하는 것 (층 1)

흐름에 나온 등급 A·B 심볼을 §4.2 형식으로 정의한다. 형식은 §4.2 가 정본이므로 여기 옮기지 않는다.

⛔ 이 섹션이 없으면 실행자가 어휘를 어디 쓸지 몰라 형식을 **지어낸다**.
⛔ 흐름(§7-A)에 등장한 A 심볼이 여기 전부 있어야 한다 — 하나라도 빠지면 G4 위반이다.
역할 개념(B)은 설명당 한 번만 쓴다.

### C. 동작↔코드 1:1 매핑 (층 2)

**흐름(§7-A)의 단계 하나마다 블록 하나**를 쓴다.

⛔ "사용자가 관찰하는 동작"을 단위로 잡으면 한 동작이 여러 단계를 가질 때 1:1 이 깨진다.
흐름 단계를 쓰면 §7-A 와 §7-C 가 개수까지 일치해 자기 검산이 된다.

⛔ **표로 만들지 않는다.** 인용 칸이 비어도 표는 멀쩡해 보여 G1 위반이 안 보인다 —
블록이면 라벨이 비는 것이 바로 드러난다.

```markdown
### 동작: {사용자가 관찰하는 것 한 문장}

**담당 코드**: `Path/File.ext:120` — `SymbolName`
**하는 일**: {이 코드가 수행하는 일}
**없으면**: [기계적|추론] {관찰 가능한 결과}
**왜 여기인가**: [실측:N|문서:X|추론] {이 계층·이 타입에 놓인 근거}
**상태**: {호출 스킬이 정하는 슬롯}
```

`상태` 슬롯은 호출하는 스킬이 값을 정한다. 슬롯은 이 하나만 둔다 — 여럿이면 템플릿이
추상화되어 읽기 어려워진다.

### D. 구조 근거 (층 3)

```markdown
## 왜 이 구조인가

### {추상화 이름}이 프로토콜인 이유
채택자: {구현체 목록} [실측: 채택자 N]
주입 지점: `Path/Builder.ext:88`
구체 타입을 직접 쓰지 않는 대신 {얻는 것}.
새 구현을 넣으려면 {절차}만 하면 된다.

### 만약 주입 대신 직접 생성했다면
[기계적|추론] {생길 문제}
```

마지막 항목이 확장성 설명의 실체다 — 대안과 비교하지 않으면 "주입받는다"는 사실 서술로 끝난다.

### E. 탐색 경계 (부록)

```markdown
## 이 문서가 다루지 않은 것

- 홉 한계로 중단: `SymbolA`의 상위 호출자 (진입점 미도달)
- 예산 초과로 제외: `FileB`의 항목 3건
- 탐색 실패: `SymbolC` — 심볼 조회 오류, 수동 확인 필요

탐색한 심볼: {N}개 / 상한 40
```

⛔ 잘린 것이 없어도 이 섹션은 쓴다. "없음"을 명시하는 것과 섹션이 없는 것은 다르게 읽힌다.

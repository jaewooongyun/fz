## 1. 이 모듈이 겨누는 것

설명이 실패하는 자리는 셋이고, 셋 다 **내용이 틀려서가 아니라 형식이 없어서** 생긴다.

```
낯선 이름이 정의 없이 등장     → 문장은 읽히는데 뜻이 안 잡힌다
"누가" 만 있고 "어떻게" 가 없다  → 주체는 알겠는데 코드로 못 찾아간다
근거 종류가 산문에 녹아 있다    → 확인된 사실과 짐작을 구분할 수 없다
```

이 모듈은 그 형식을 정한다. ⛔ 문체 교정 자체는 외부 스킬 소관이며 §8 이 연동만 정한다.

## 2. 세 축

목표를 세 마디로 두면 각 마디가 지탱하는 장치가 다르다.

| 목표 | 축 | 장치 |
|------|-----|------|
| 가독성 | 문체·배치 | G6 정리 · G7 층위 · G8 문체 |
| 전체 상황 설명 | 범위 | 폐포 5축 · 출력 §7-A 흐름 |
| 동작↔코드 1:1 | 정확성 | G1 인용 · G4 어휘 · G5 경로 · 출력 §7-C 매핑 |

셋은 직교한다 — 범위가 맞아도 어휘가 없으면 문장이 안 읽히고, 배치가 평면이면 따라오지 못한다.

⛔ **게이트를 늘리지 않는다.** 추가 전에 묻는다 — "이 게이트가 잡았을 구체적 실패를 댈 수
있는가?" 못 대면 추가하지 않는다. 규칙이 불어나면 준수율이 떨어진다.

## 3. 폐포 — 무엇을 다룰지

"연관된 모든 구조"를 문자 그대로 실행하면 후보가 코드베이스 전체가 된다. 폐포는 그 확장을
유한하게 끊는 장치다.

### 3.1 Seed

⛔ seed 산출은 **호출하는 스킬이 정한다** — 이 모듈은 seed 가 주어진 뒤부터를 규정한다.

⭐ **경량 변형도 스킬 소관이다.** 축을 줄이거나 예산을 낮추거나 층을 생략하는 것은 소비자마다
뜻이 다르다 — 같은 `--light` 라도 어떤 스킬은 상위 티어로 내려가고 어떤 스킬은 층을 뺀다.
정본이 변형을 전부 알면 오히려 소비자에 결합된다. **단 무엇을 줄였는지 스킬이 명시**하고,
G1 인용과 §7-E 탐색 경계는 어느 변형에서도 생략하지 않는다.
seed 는 파일이 아니라 **심볼**이어야 한다. 한 줄 수정도 그 심볼 전체를 seed 로 올린다.
그래야 §3.2 의 관계 탐색이 성립한다.

### 3.2 탐색 축 5종

각 seed 심볼마다 아래 다섯 방향으로 탐색한다. 축마다 홉 한계와 종료 조건이 다르다.

| 축 | 무엇을 찾나 | 홉 | 주 도구 |
|----|------------|-----|---------|
| R1 진입점 | 사용자 동작이 들어오는 첫 지점 | 최대 5 | find_referencing_symbols |
| R2 협력자 | seed가 호출하는 필수 대상 | 1 | find_symbol |
| R3 계약 | 채택한 protocol + 다른 채택자 | 1 | find_symbol, Grep |
| R4 배선 | 구현체 생성·주입 지점 | 2 | Grep, find_referencing_symbols |
| R5 소비자 | seed의 결과를 쓰는 상위 | 1 | find_referencing_symbols |

**R1 진입점**은 역방향으로 거슬러 올라가되 셋 중 **먼저 닿는 것**에서 멈춘다 —
프레임워크 콜백 경계(버튼 액션·라이프사이클·라우팅 진입) · 역참조 0 · **5홉**.
5홉에서 끊긴 경우 그 사실을 §7-E에 적는다.

R1에만 다섯 홉을 주는 이유는 진입점이 대개 여러 계층 위에 있기 때문이다. ⛔ 다른 축은 1~2홉이다.

**R3 계약**이 핵심 축이다. "왜 이 구조가 주입을 받는가"를 답할 재료가 여기서 나온다.

⛔ **채택자 수는 "현재 다형성 사용 현황"이지 설계 의도가 아니다.** 관측에서 의도를 곧바로
끌어내면 G3 이 막으려는 비약이다 — 이유를 단정하려면 설계 문서·커밋·주입 지점 같은 별도
근거가 있어야 하고, 없으면 `[추론]` 으로 적는다.

⛔ 채택자를 셀 때 0건이나 1건이 나오면 **측정 실패를 먼저 의심한다**. 경로가 틀렸거나 심볼명이
다를 수 있다. 성질이 다른 두 도구로 교차 확인한 뒤에만 숫자를 적는다.

1개여도 그대로 적되 ⛔ "테스트 대역이겠거니" 로 **이유를 지어내지 않는다** — 근거가 없으면
"채택자 1 [실측]" 까지만 쓰고 이유는 `[추론]` 으로 명시한다.

**R4 배선**에 2홉을 주는 이유는 1홉이면 "주입받는다"까지만 보이고 "누가 넣어주는가"가 안 보이기 때문이다.

### 3.3 예산과 절단 기록

```
총 탐색 심볼 상한: 40 (중복 제거 후 고유 심볼 기준)

순회 순서:  seed 우선순위 → 각 seed 마다 R1 → R2 → R3 → R4 → R5
seed 우선순위: ① 호출 스킬이 명시한 대상  ② 역참조 수가 많은 것  ③ 이름 사전순 (동률 해소)
중단:       예산에 도달하면 **그 자리에서 멈춘다.** 진행 중인 축을 마저 돌지 않는다
한 seed 초과: seed 하나로 40을 넘으면 그 seed 만 다루고 나머지 seed 는 전부 §7-E 에 기록
```

⛔ 순서·중단을 못 박는 이유는 **재현**이다 — 같은 입력에서 다른 폐포가 나오면 비교가 안 된다.

⛔ **절단한 것은 반드시 §7-E에 기록한다.** 조용한 절단은 독자에게 "이게 전부"로 읽힌다.
무엇이 왜 빠졌는지 적지 않으면 완결성을 거짓으로 주장하게 된다.

## 4. 어휘 등급 — 어떻게 소개할지

"낯선 용어를 설명하라"는 무한 확장이므로 경계를 **출처**로 긋는다 — 독자가 검색으로 못 찾는
것만 설명 의무가 있다.

| 등급 | 무엇인가 | 의무 |
|------|---------|------|
| A | 이 저장소에 정의된 심볼 | 정의 + 인용 필수 |
| B | 프레임워크·라이브러리 개념 | 한 줄 역할 + 이 프로젝트에서의 형태 |
| C | 언어·일반 개념 | 설명하지 않는다 |

판별은 기계적이다. 저장소 안에 정의가 있으면 A, import 한 모듈에 있으면 B, 언어 키워드면 C다.

### 4.1 파생 B 의무

⭐ A 등급 심볼의 **역할 접미사가 프레임워크 개념이면 B 의무가 파생된다.** 한 심볼이 두 줄을 받는다.

```
{Feature}Builder    → A(이 타입이 무엇을 만드나) + B(프레임워크에서 Builder 의 역할)
{Feature}Router     → A + B
{Feature}Listener   → A + B(상위로 알리는 규약)
```

역할 개념은 **설명당 한 번만** 쓴다. 같은 접미사가 여러 번 나와도 개념 설명은 처음 한 번이다.

### 4.2 정의 형식

```
{심볼} [A|B]
선언:      `{시그니처}` — path/File.ext:line     (A는 인용 필수)
하는 일:    {한 문장}
왜 지금 나오나: {이 설명의 어느 대목과 연결되는지}
```

마지막 줄이 있어야 읽기가 끊기지 않는다. 용어집을 뒤에 몰아두면 독자가 왕복해야 한다.

⛔ 비유로 치환하지 않는다. 익숙한 사물에 빗대면 추상적 이해만 남고, 코드로 돌아갔을 때
그 비유는 거기 없다. 타입 정의를 그대로 보이는 편이 짧고 정확하다.

## 5. 게이트 8종

산출물 중 여럿은 **코드에 직접 쓰여 있지 않아** 유창하게 지어낼 수 있다. 게이트가 그 경로를 막는다.

| 산출물 | 코드에 있나 | 게이트 |
|--------|-----------|--------|
| 하는 일 | 있다 | G1 |
| 없으면 생기는 문제 | 없다 | G1 + G2 |
| 왜 이 역할·왜 주입인가 | 없다 | G1 + G3 |

⛔ 각 게이트의 `근거:` 는 **등급이 다르다** — `관측`(확인된 실패) · `사용자 요구` · `[추론]`
(전제는 그럴듯하나 미관측). `[추론]` 게이트를 `관측` 게이트와 같은 무게로 확대하지 않는다.

### G1 인용 게이트

근거: [추론] — 인용 없는 매핑은 짐작인데, 이 유형의 실패를 아직 관측하지 못했다.

판정: 모든 매핑 블록이 `path/File.ext:line` **과** 심볼명을 **둘 다** 가진다.
위반 시: 블록을 **삭제한다**. `[미검증]` 태그로 남기지 않는다.

⛔ "또는"이 아니라 "그리고"다. 심볼명만 있으면 독자가 파일을 찾아 헤매고, 줄번호만 있으면
무엇을 보는지 모른다. 소비자 test-spec 과 fixture 도 `file:line` 을 필수로 잰다.

인용하지 못하는 매핑은 매핑이 아니라 짐작이고, 짐작을 1:1 매핑 자리에 두면 독자가 그것을
코드 사실로 읽는다.

### G2 반사실 등급 게이트

근거: [추론] — 근거 종류가 산문에 녹으면 독자가 구분하지 못한다. 모델 산출 관측은 아직 없다.

판정: "없으면 어떤 문제가 생기나"에 두 등급 중 하나가 붙어 있다.
위반 시: 등급을 못 붙이면 그 항목을 **쓰지 않는다**.

```
[기계적]  관찰 가능한 메커니즘을 지목할 수 있다.
          컴파일 에러 / 프로토콜 미충족 / nil 경로 / 등록 누락으로 인한 미호출.
          → 경로를 문장 안에 적는다.

[추론]    그 외 전부. 근거가 설계 상식이거나 유사 패턴 유추일 때.
```

### G3 근거 등급 게이트

근거: [추론] — G2 와 같은 축. 실측과 추론이 같은 문체로 서술되면 구분이 사라진다.

판정: "왜 이 구조인가", "왜 주입을 받는가"에 근거 출처가 붙어 있다.
위반 시: 출처를 못 대면 `[추론]` 으로 낮춰 적는다.

```
[실측: 채택자 3]   R3에서 실제로 세었다. 숫자를 적는다.
[실측: 호출자 7]   R5에서 실제로 세었다.
[문서: {문서명} {섹션}]  프로젝트 규칙에 명시돼 있다.
[추론]             위 셋 어디에도 해당하지 않는다.
```

숫자를 적는 이유는 검산이 가능해지기 때문이다. "여러 곳에서 쓴다"는 반증할 수 없지만
"채택자 3"은 반증할 수 있다.

⛔ **`[추론]` 이 도피처가 되지 않게 한다.** 한 문서의 근거가 대부분 `[추론]` 이면 구조를
설명한 것이 아니라 짐작을 나열한 것이다.

```
G3 근거 중 [추론] 이 절반을 넘으면 → §7-E 탐색 경계에 그 사실을 적는다
```

⭐ 막지 않고 **드러낸다** — 추론이 많은 것 자체는 죄가 아니고 독자가 모르는 것이 문제다.

### ⚠️ G2 와 G3 를 합치지 않는 이유

둘 다 "근거 종류를 밝혀라"로 보이지만 **대상과 라벨 체계가 다르다.**

```
G2  대상 = 존재하지 않는 코드의 인과      라벨 = [기계적] · [추론]
G3  대상 = 설계 의도                    라벨 = [실측:N] · [문서:X] · [추론]
```

`[기계적]`(메커니즘을 지목할 수 있다)과 `[실측:N]`(세어 봤다)은 다른 축이다. 합치면 라벨이
다섯이 되고 어느 필드에 무엇을 쓸지 모호해진다 — 판정이 흐려지는 쪽으로 간다.

### G4 어휘 게이트

근거: 관측 — 독자가 낯선 타입 넷을 두고 "이건 뭔가"를 되물었다.

판정: 등급 A·B 심볼이 첫 등장 시 §4.2 형식으로 정의된다. A 심볼의 역할 접미사가 프레임워크
개념이면 파생 B 도 함께 나온다.
위반 시: 정의를 추가하거나, 그 심볼을 쓰지 않고 서술을 바꾼다.

### G5 경로 게이트

근거: 관측 — 독자가 "누가 띄우나"는 알겠는데 "어떻게 띄우나"를 못 찾았다.

판정: 주체나 경로를 지목하는 동작 서술이 심볼 호출 시퀀스로 전개돼 있다.
2단계 이상이면 산문 요약을 쓰지 않는다.
위반 시: 홉·단계마다 심볼을 인용한 체인으로 편다.

```
전:  "실제로 화면을 올리는 건 상위 컴포넌트였다"
후:  탭 → `A.onTap()` → `listener?.wantsX()` → `B.wantsX()`(전달만)
     → `C.route()` → 여기서 처음 실제 push
```

⭐ 홉마다 "전달만 한다"도 정보다. 오히려 그게 비용의 실체를 보인다.

### G6 정리 게이트

근거: 사용자 요구 — 중간 한 줄 정리가 이해를 도왔다는 직접 진술.

판정: 각 섹션이 한 줄 요약으로 닫힌다.
위반 시: 요약을 추가한다.

요약은 그 섹션에서 가져갈 명제 하나여야 하고 방금 쓴 내용의 반복이 아니어야 한다.
⛔ 반복 여부는 기계로 못 잰다 — 존재만 검사하고 질은 작성자가 지킨다.

### G7 층위 게이트

근거: 관측 — 점층 없이 원문 순서대로 평면 배열한 산출물이 이해를 돕지 못했다.

판정: 섹션이 §6 의 층 0~3 순서로 배치돼 있다. 어려운 것이 앞에 오지 않는다.
위반 시: 순서를 바꾼다.

### G8 문체 게이트

근거: 사용자 지시 — 한국어 가독성 스킬을 활용하라는 직접 요청. ⛔ 관측 아님.

판정: §8 절차를 거쳤고 기계 검사 4종이 통과한다.
위반 시: 해당 패턴을 고친다.

---

## 6. 난이도 층위

한 문서가 세 수준을 다 담는다. 독자가 고르는 것이 아니라 문서가 순서대로 데려간다.

| 층 | 수준 | 담는 것 |
|----|------|--------|
| 0 | 요지 | 한 단락. 이것이 무엇인지 |
| 1 | 기초 | 무엇을 하나 · 등장 인물 소개 (어휘 A·B 정의가 여기) |
| 2 | 중급 | 어떤 순서로 동작하나 · 동작↔코드 1:1 매핑 |
| 3 | 심화 | 왜 이 구조인가 · 없으면 무엇이 깨지나 · 확장 지점 |

층 0 을 두는 이유는 요지가 뒤에 있으면 독자가 근거부터 읽고 헤매기 때문이다.

## 7. 출력 구조

⛔ 마크다운 파일로 끝낸다. 다른 출력 형식은 이 모듈의 범위 밖이다.

섹션 형식은 **`modules/explanation-output.md`** 가 정본이다 — 층위별 A~E 다섯 섹션의
템플릿이 거기 있다. 실행 전 Read 한다.

```
A  기능 전체 흐름 (층 0~1)      진입점 → 소비자, 단계마다 파일 인용
B  등장하는 것 (층 1)           A 에 나온 A·B 등급 심볼 정의
C  동작↔코드 1:1 매핑 (층 2)    흐름 단계마다 블록 하나
D  구조 근거 (층 3)             왜 이 구조인가 + 대안 비교
E  탐색 경계 (부록)             홉·예산으로 잘린 것
```

⛔ 형식을 여기 옮겨 적지 않는다. 두 곳에 있으면 서서히 어긋난다.

## 8. 문체 — 마지막에 다듬는다

⭐ **순서가 규칙이다.** 구조와 인용이 확정된 뒤 문체를 손본다 — 먼저 다듬으면 이후 편집이
다시 기계 문체를 만든다. 이 절이 §7 뒤에 있는 것도 그 때문이다.

### 8.1 연동

한국어 문체 교정 스킬을 **내장 모드**로 호출한다 — 최종본만 돌려받는다.
그 스킬은 산문만 고치고 코드 블록·데이터·링크 대상은 건드리지 않는다.

⛔ **호출 주체는 Lead 다** — 문서 저장과 같은 축이므로 소비자 스킬의 `allowed-tools` 에
`Skill` 을 넣지 않는다.

⛔ 인용은 백틱이나 코드 블록 안에 둔다. 문장을 합치고 쪼개는 과정에서 산문에 노출된
`file:line` 은 재배치될 수 있다. 코드 영역 불가침이 이 제약의 근거다.

### 8.2 기계 검사 4종

교정 스킬을 쓸 수 없는 환경에서도 아래는 센다.

```
과잉 볼드      한 문단에 볼드가 셋 이상
명사형 제목    서술어 없는 제목의 연속
장식 이모지    의미 없는 이모지
줄표 남용      한 문단에 둘 이상
```

### 8.3 내장 산문 규칙 3종

⛔ 기계 검사 4종은 전부 **형식** 신호라 번역투·수식어 중첩을 못 잡는다. 교정 스킬이 없으면
아래 셋만이라도 지킨다.

```
P1 번역투 구      `~에 대한` · `~를 통하여` · `~에 있어서` 를 조사로 바꾼다
P2 수식어 중첩    한 명사에 관형어 셋 이상을 붙이지 않는다
P3 한자어 명사화  `수행하다` · `진행하다` 로 끝나는 동사구를 서술어로 되돌린다
```

⛔ 셋만 둔다. 교정 스킬의 패턴 전체를 복제하면 두 자산이 어긋난다. 상세 판정은 그 스킬 소관이고
이 모듈은 부재 시의 바닥만 지킨다.

## 9. 실행 절차

```
T1  seed 확보         호출 스킬이 산출 (§3.1)
    verify: seed 가 파일이 아니라 심볼인가

T2  폐포 탐색          각 seed 에 R1~R5, 예산 40 카운트 (§3.2)
    verify: 결과 0건인 축을 다른 도구로 재확인했는가

T3  어휘 등급 부여      등장 심볼을 A/B/C 로 나누고 파생 B 판정 (§4)
    verify: A 심볼 중 정의가 빠진 것이 0건인가

T4  층위 배치          층 0~3 에 내용을 배당 (§6)
    verify: 심화 내용이 앞에 오지 않았는가

T5  게이트 적용         G1~G7 (§5)
    verify: 등급 라벨이 빠진 항목이 0건인가

T6  문체 다듬기         교정 스킬 내장 모드 → 기계 검사 4종 (§8)
    verify: §7-A 의 각 단계가 §7-C 에 블록으로 존재하는가
```

T6 의 verify 가 자기 검산이다. 흐름에는 나오는데 매핑 블록이 없는 단계가 있으면
그 단계는 인용 없이 서술된 것이다.

### 대화 출력

문서와 달리 대화에는 요약만 낸다.

```
1. 한 줄 요약
2. 기능 흐름 (단계 제목만, 코드 인용 없이)
3. 이번 설명이 다룬 범위
4. 문서 경로 안내
```

⛔ 매핑 블록 전문 · 구조 근거 본문 · 탐색 경계는 대화에 내지 않는다.
